# RESEARCH 1 – "Delegation treated as authority; author-controlled briefs"

Version: v2 (English) · Date: 11.10.2026

**Legend:**
- **[OFFICIAL]** – Anthropic documentation
- **[PRACTICE]** – how Anthropic or other major players work in practice
- **[READY-MADE]** – community repository or skill you can inspect
- **[CONSTRUCTION]** – assembled from official mechanisms; no ready-made implementation found

"I assume" marks my own inference, not source content. Numbers in square brackets [n] refer to the source list at the end.

---

## 0. Key findings

1. There is no official mechanism that separates "a helper said it" from "verified". There are official building blocks: subagent start and stop hooks, a hook before the Agent tool call, transcripts on disk, and agent-type hooks. Gates can be built from these.
2. In its own products, Anthropic solves the problem through architecture rather than discipline. A **different** agent scores or reproduces each helper finding, and anything unverifiable is dropped (code-review, ultrareview).
3. The strongest pattern against answer-framing briefs is the **blind reviewer**. In phase one it gets the spec and raw material, without the author's report or framing.
4. For high volumes of remarks (e.g. 174), the practice is confidence scoring with a threshold plus a separate verifier per finding, never batch acceptance.
5. The weakest-covered areas are an enforced, fixed brief template and a coverage register. Only constructions exist there; no ready-made implementations were found.

## 1. Official recommendations and mechanisms

### 1.1 What the documentation itself acknowledges (root of the problem)

- **The author writes the brief.** A subagent starts with an empty context and does not see the conversation history. Claude itself composes the delegation message summarizing the task, and the subagent works only from that message [1].
- **A subagent cannot ask the user.** The AskUserQuestion tool is removed from every subagent, even if it is listed in the subagent's tools [1].
- **What comes back is a summary, not evidence.** The documentation describes a subagent as doing the work in its own context and returning only a summary [1].

### 1.2 Hard mechanisms (building blocks for gates)

| Mechanism | What it offers against the problem | Certainty |
|---|---|---|
| **SubagentStop hook** | Can block the subagent from finishing and send it a reason. Hooks can be defined in the subagent's frontmatter or in settings.json, and SubagentStart/SubagentStop fire when a subagent starts or finishes [1]. The hook input includes the path to the subagent's transcript (agent_transcript_path), i.e. the raw path to the evidence [4]. | certain |
| **PreToolUse hook with matcher `Agent`** | Controls the brief **before** it is sent. It can block (exit 2), add context (additionalContext) or rewrite the input (updatedInput) [4]. This allows enforcing a brief template or injecting current data (e.g. a version map) instead of the author's memory. | mechanism certain; use for briefs is [CONSTRUCTION] |
| **`prompt` and `agent` hook types** | A prompt hook evaluates text with a model but cannot open files. That requires an agent-type hook, which spawns a subagent able to read files and run commands [12]. Only this type can actually verify a helper's claim. | certain |
| **Subagent transcripts on disk** | Stored at `~/.claude/projects/{project}/{sessionId}/subagents/agent-{agentId}.jsonl` [1]. This is audit material for what the helper actually did, not only what it said it did. | certain |
| **"No authority" header and output scan** | A subagent's report arrives under a header stating that instructions and approval claims inside it are the subagent's words, carrying no user authority [1]. **Limitation:** the scan does not judge whether content is true. It protects against injected instructions, not against false facts [1]. | certain |
| **Nested verifier** | The documentation gives an example of a reviewer subagent that dispatches a separate verifier per finding [1]. This is the official pattern for large numbers of findings. | certain |
| **SendMessage to `main`** | A subagent receives a sibling roster in which `main` is listed as a valid message recipient [1]. This is a partial answer to "the agent cannot ask". **I assume** it can serve as a question channel to the lead. The docs describe it as messaging, not as a question mechanism, and the roster appears only when another named agent exists. | partially certain |
| **Effort and turn limit per invocation** | Claude can pass an effort level for a specific invocation, overriding the definition's effort. When a subagent hits its turn limit, its output is marked as partial, so incomplete work cannot pass as complete [1]. | certain |
| **Skill preloading** | The full content of listed skills is injected into the subagent's context at startup [1]. Fixed working rules (e.g. "no findings is an allowed outcome", "cite file:line") then no longer depend on the brief author's memory. | certain |
| **Fork** | A fork inherits the entire conversation instead of starting fresh [1], which removes the "brief written from memory" loss. **Downside:** it also inherits the author's framing, so it is not independent. | certain |
| **Agent teams** | Teammates communicate directly, share a task list, and can challenge each other's findings [5]. TaskCreated and TaskCompleted hooks with exit code 2 block task creation or completion with feedback [6]. | certain (experimental feature) |

### 1.3 Soft official recommendations

- **Brief as a contract.** Each subagent needs an objective, an output format, guidance on tools and sources, and clear task boundaries. Without these, agents duplicate work, leave gaps or miss necessary information [2].
- **Do not narrow the reviewer in the brief.** Instructions like "report only high-severity issues" or "be conservative" may be followed literally, so the model reports less. The recommendation is to ask it to report everything and filter in a separate pass [3]. This is an official argument against word caps and against framings like "the only allowed difference".
- **Counterpoint (cost).** The Opus 5 guide advises against using subagents to verify or double-check the model's own work, because the model already self-verifies and extra verification instructions cause over-verification [3]. **I assume** this applies to checking one's own work, not to checking helper claims. The methodology should keep these two cases apart.
- **Fresh context for assessment.** When unbiased analysis matters, ask for a fresh context [7].

### 1.4 What does NOT exist officially (not found)

- A claim status such as "reported" vs "verified" in the flow of helper output.
- A brief validator or a built-in brief template.
- A coverage register (which area had no helper).
- A register of helper errors.

## 2. How the major players handle it

### 2.1 Anthropic – Research system [PRACTICE] [2]

- **Brief as contract, with explicit exclusions.** Short instructions like "research X" proved too vague. In one case, one subagent researched the 2021 automotive chip crisis while two others duplicated work on 2025 supply chains.
- **Effort rules written into the prompt.** Agents misjudge how much effort a task needs, so scaling rules were embedded in prompts, ranging from one agent with a few tool calls up to more than ten subagents for complex research.
- **Artifacts instead of summaries.** Subagents store their work in an external system and pass lightweight references back to the coordinator. This reduces information loss, which Anthropic calls the "game of telephone".
- **A separate citation agent (CitationAgent).** Every claim in the report is attributed to a specific location in a source.
- **A judge with a rubric.** It checks whether claims match sources, whether citations are accurate, and whether coverage is complete. Human testing supplements it by catching what evals miss.

### 2.2 Anthropic – official code-review plugin [PRACTICE + READY-MADE] [8]

- Several agents look for issues, then each finding receives a confidence score from 0 to 100.
- The finding agents do not score their own findings, and the default cutoff threshold is 80.
- For CLAUDE.md-based issues, the scorer must confirm the guideline explicitly states the rule. This directly targets errors of the "X already does Y" type.
- Where to look: `anthropics/claude-plugins-official → plugins/code-review/commands/code-review.md`.

### 2.3 Anthropic – ultrareview [PRACTICE] [9]

- Every finding is independently reproduced and verified.
- A different set of agents does the verification than the set that found the candidates.
- Anything that cannot be independently confirmed does not reach the report.

### 2.4 Agent tool prompt in Claude Code [PRACTICE, secondary source] [10]

- Analyses of Claude Code's source report a rule "Never delegate understanding", which forbids instructions like "based on your findings, fix the bug".
- The prompt should be a complete briefing for someone who knows nothing about the session.
- **Caveat:** these are community analyses, not documentation.

### 2.5 Cognition (Devin) [PRACTICE, opposing stance] [11]

- Core principle: share context and full agent traces, not individual messages. Architectures that violate this should be ruled out by default.
- Takeaway for this problem: pass paths to full traces instead of better summaries.

## 3. How the community handles it – ready-made resources

| Ready-made | What it solves | Details |
|---|---|---|
| **obra/superpowers – subagent-driven-development** [13] | adopting a report without checking | The reviewer template tells the reviewer not to trust the implementer's report and to verify the code line by line. Warning from v6.0: compressing review context too aggressively can make the agent hallucinate the spec [14]. |
| **superpowers – receiving-code-review** [15] | accepting auditor remarks at face value | Order of steps: read, restate, check against reality, evaluate, then respond or push back with reasoning. If anything is unclear, stop and ask. If verification is impossible, state plainly what is missing. |
| **superpowers – verification-before-completion** [15] | claims without evidence | Before claiming success, run the verification and confirm its output. Rule: evidence before assertions. |
| **compose-subagent (XiaomiMiMo/MiMo-Code, arborlogic/openzerocode)** [16] | **briefs and reports that steer the reviewer** | Two-phase blind review. Phase 1 receives only the spec and the change, without the implementer's report, because its claims anchor the reviewer. The report appears in phase 2 only to explain flagged items, and it can only lower the verdict. The reviewer must be at least as capable as the implementer, since a weaker one shares its blind spots. |
| **ek33450505/attest** [17] | "DONE" without backing | SubagentStart snapshots the files; SubagentStop compares actual changes with the subagent's claim. In enforce mode, a false DONE is blocked. |
| **vnmoorthy/groundtruth** [18] | completion claims without evidence in the same turn | A Stop hook refuses to end a turn that claims completion without verification. It also includes a transcript audit that flags unverified claims. |
| **84em – Stop hook for unverified claims** [12] | **numbers and second-hand facts** | Catches version numbers, prices, default values, file contents, dates and identifiers. The agent must verify them or mark them as unverified. |
| **buildthisnow – research agent** [19] | report without an evidence register | An evidence ledger, a search for disconfirming evidence, and a SubagentStop validator that blocks a report missing required sections or sources. |
| **claudefa.st – report skeleton** [20] | summary indistinguishable from fact | The report's first line is the outcome with a proof token (SHA, test count, URL, file:line). The evidence sits in the same bullet as the claim. |
| **constellos/claude-code-kit** [21] | brief and coverage register | SubagentStart saves the brief, type and agent ID to a state file; SubagentStop processes the transcript. This is a basis for a brief register and a gap audit. |
| **christophermark gist – delegation policy** [22] | delegating the thinking | Ambiguous design work is never delegated, because writing the spec is the work. Bulk output goes to a scratch directory on disk. |

## 4. Map: symptom from the description → best-fit remedy

| Symptom | Remedy | Type |
|---|---|---|
| False helper/auditor claims adopted | Per-claim verifier (pattern: code-review, ultrareview, nested verifier from the docs), Stop hook for unverified numbers and facts, receiving-code-review discipline | official + ready-made |
| Report edited from hand-back summaries before helper files were opened | Artifacts on disk plus references (Anthropic). A PreToolUse hook on report edits that checks the transcript for a read of the helper's file | practice + [CONSTRUCTION] |
| Briefs written from memory (e.g. wrong version map) | PreToolUse(Agent) hook injecting current data (additionalContext or updatedInput); skill preloading; optionally a fork | [CONSTRUCTION] on official building blocks |
| Answer-framing briefs, "independent" helpers, word caps | Two-phase blind review; "report everything, filter separately"; reviewer at least as capable as the implementer | ready-made + official |
| Missing promised clauses, effort, evidence limits, raw path | Fixed brief template and a PreToolUse(Agent) hook that blocks briefs missing required sections (exit 2); per-invocation effort; transcript path from SubagentStop | [CONSTRUCTION] |
| Coverage gaps (areas without a helper) | Brief register from SubagentStart plus an artifact coverage list checked before synthesis; TaskCreated and TaskCompleted hooks in agent teams | ready-made + [CONSTRUCTION] |
| Helpers' own errors not recorded | Helper-error register fed by verifier results; optionally the subagent memory field | [CONSTRUCTION] |
| Agent cannot ask | SendMessage to main (partial), agent teams (messages to the lead, plan approval), implementer status codes such as "needs context / blocked" (superpowers) | official + ready-made |
| High volume of remarks invites batch acceptance | Confidence scoring with a threshold, a separate scorer, deduplication | official plugin |

## 5. Pitfalls found along the way

- **Block limit.** Claude Code overrides a Stop hook after eight consecutive blocks to avoid trapping the agent in a loop [12]. The gate is therefore not absolute.
- **Folder trust.** Frontmatter hooks of a project subagent run only after the folder trust dialog is accepted. Until then the subagent still runs, but its hooks are skipped [1].
- **Non-deterministic self-correction.** The attest author admits that self-correction after a block is not reproducible [17].

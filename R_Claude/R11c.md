# R11 — Making Claude Code design remedies with real option, impact and bypass analysis (v1)

Claude Code has no single official feature that makes the agent do systematic option and impact analysis when it designs remedies. What works in practice is a combination you build yourself: (1) a mandatory remedy-design skill/template that forces a "built-in first / do nothing / remove" option list plus replay, bypass, interaction and cost sections; (2) a fresh-context adversarial reviewer subagent that is told to attack the design against the real incident; (3) a deterministic replay harness that pipes the incident's actual tool calls and the owner's real prompts through every proposed hook or rule; and (4) the built-ins Anthropic itself documents as the real enforcement layer (permission deny/ask rules, sandbox, protected paths, auto-mode classifier, `onFailure: "block"`). Text-only remedies are explicitly ruled out by Anthropic's own docs.

## TL;DR
- **No official "remedy design" mechanism exists**, but Anthropic's docs supply most of the parts: plan mode, a documented "adversarial review step" with a fresh-context subagent, the statement that CLAUDE.md is advisory while hooks/permissions are enforced, explicit documentation that Bash rules are not a security boundary, and (since v2.1.295, Oct 8 2026) `onFailure: "block"` for fail-closed hooks. Your R11 failure, where every cause got a bespoke hook, runs against the documented hierarchy: permission rules and sandboxing first, hooks only for logic rules can't express.
- **The most effective fix is a gated pipeline, not a better prompt**: a remedy-design skill with a fixed template (options incl. built-in / do-nothing / remove → replay matrix against incident turns and real prompts → bypass list → interaction inventory → failure mode → cost → "rejected-reasons" check), then an independent red-team subagent in fresh context, then a scripted replay test of every hook. Community artifacts (Superpowers brainstorming/writing-skills, contrarian, devils-advocate, crucible red-team, agent-review-panel, ADR skills, hook test harnesses) cover each piece, but none covers the whole of R11 out of the box.
- **Treat any remedy that can't be replayed and can't fail closed as unfinished.** Anthropic's own auto-mode work is the model to copy: an internal incident log, a labeled set of real overeager actions (n=52), measured false-negative/false-positive rates (17% FNR, 0.4% FPR), and evaluation of an action's real-world effect rather than its surface text. That is exactly the replay-against-real-data step that R11 skipped.

## Key Findings

1. **Anthropic's docs define an enforcement hierarchy that R11 ignored.** Permission rules "are enforced by Claude Code, not by the model. Instructions in your prompt or CLAUDE.md shape what Claude tries to do, but they don't change what Claude Code allows."\[1\] Best-practices adds that hooks, "unlike CLAUDE.md instructions which are advisory, … are deterministic and guarantee the action happens."\[2\] So "an oath" or "a habit in the reviewer definition" is by definition not a remedy for anything that must hold. (Verified, official docs.)
2. **The docs already list the bypass paths R11 failed to enumerate.** A Bash deny rule "isn't a security boundary around the program": `Bash(rm *)` doesn't stop `/bin/rm` or `bash -c 'rm …'`, and `Bash(git push *)` doesn't stop `git -C . push`. Read/Edit deny rules "don't apply to … arbitrary subprocesses that read or write files indirectly, like a Python or Node script." The official fix is the sandbox for OS-level enforcement.\[1\]\[3\] (Verified.) Any proposal built on Edit/Write rules or Bash string matching must therefore list "script via Bash" and "alternate invocation" as known holes.
3. **Hooks fail open by default; fail-closed is opt-in and recent.** Only exit 2 blocks; exit 1, crashes and timeouts are non-blocking errors, and "a timed-out command, http, or mcp_tool hook doesn't block the tool call."\[4\]\[5\]\[6\] v2.1.295 (Oct 8, 2026) added `onFailure: "block"` for command and HTTP hooks. Prompt, agent and MCP-tool hooks are not covered. Developers Digest tested this independently (Oct 9, 2026; six `claude -p` runs on v2.1.295). Without the setting, a missing script path and a timed-out guard (30 s sleep, `timeout: 3`) both let `echo` run, and "the final answer gave no sign that the guard had not run; the command simply executed." With `onFailure: "block"`, both were blocked. (Verified: docs, changelog, third-party reproduction.)
4. **Plan mode is not a hard read-only boundary.** Official docs: "Claude reads files, runs shell commands to explore, and writes a plan, but does not edit your source." With auto mode available, the classifier approves shell commands during planning.\[1\] In interactive sessions with bypass permissions available, "Claude Code also doesn't enforce plan mode's blocks."\[7\]\[8\] GitHub issues (#32768, #39713, #13732) report destructive Bash running in plan mode.\[9\]\[10\]\[11\] (Verified.) Plan mode is a design-phase aid, not a guardrail.
5. **Anthropic's own guardrail design is the clearest example of "replay against real data".** The auto-mode post describes an internal incident log of agentic misbehaviors, a real-traffic set (n=10,000), a curated real overeager set (n=52) and a synthetic exfiltration set (n=1,000). It publishes the miss rate (17% FNR on real overeager actions) and states the classifier evaluates "the real-world impact of an action, rather than just the surface text." It also weighs approval fatigue explicitly: Anthropic's telemetry showed "users approved roughly 93% of permission prompts." (Verified, Anthropic Engineering, Mar 25 2026.)
6. **Option generation is enforced only by community skills.** Superpowers' brainstorming skill mandates "Propose 2-3 approaches — with trade-offs and your recommendation" and "YAGNI ruthlessly" before any implementation.\[12\]\[13\] It does not mandate a "do nothing", "remove" or "built-in feature" option. That gap is exactly R11's. (Verified, skill text.)
7. **Superpowers' writing-skills gives the closest community template for "replay before deploy".** It requires baseline pressure scenarios run with subagents without the rule, documenting the failure verbatim, then re-running with the rule.\[14\]\[15\] Applied to guardrails, that is exactly "replay the real incident and the 8 real prompts before claiming the fix works." (Verified, skill text.)
8. **Fresh-context adversarial review is officially recommended, with a warning about over-engineering.** Docs: "a reviewer running in a fresh subagent context sees only the diff and the criteria you give it." They also warn: "A reviewer prompted to find gaps will usually report some… Chasing every finding leads to over-engineering."\[2\] (Verified.) This matters for R11, because a red team without a cost/"do less" lens will generate more mechanisms, not fewer.

### 2. How the biggest players handle it

- **Anthropic (verified, primary source):** The auto-mode design is a worked example of R11 done right. It starts from an internal incident log, names a threat model (overeager, honest mistakes, prompt injection, misalignment), and evaluates alternatives with data (a tool-calls-only variant "had the lowest false-negative rate still but lost the user-intent anchor"). It weighs side effects: approval fatigue and the 0.4% FPR are made "survivable" by deny-and-continue. It openly states residual risk ("not a drop-in replacement for careful human review on high-stakes infrastructure"). It also lists, in the docs, known holes for rules (broad allow rules are dropped because "the classifier never sees the commands most capable of causing damage").\[17\]
- **Anthropic internal teams (verified but thin):** The "How Anthropic teams use Claude Code" report shows TDD-first workflows (Security Engineering), feeding stack traces during incidents, and reviewing Terraform plans.\[30\]\[31\] **I found no published Anthropic practice specifically for designing agent remedies with option/impact analysis**, beyond the auto-mode post. Treat any claim otherwise as assumed.
- **Cursor / OpenAI Codex / Gemini CLI (verified via Developers Digest's Oct 9, 2026 comparison of vendor docs):** Cursor's docs say "Hook failed, action proceeds (fail-open by default)". Cursor offers `failClosed: true` per hook and fails closed on malformed output for permission hooks. Codex's docs say "Treat tool hooks as a useful guardrail, not a complete enforcement boundary" and point to sandbox and approval policy as the boundary. Gemini CLI treats "any exit code other than 0 and 2" as a warning where the action proceeds, has a 60 s default timeout, and has no documented fail-closed switch. The convergent industry position is that hooks are a guardrail and sandbox/permissions are the boundary. That directly contradicts R11's "a custom hook per cause."
- **No evidence found** of GitHub, Google or OpenAI publishing an agent-specific "remedy design review" template. Classic SRE postmortem practice (action items checked against root cause) is the closest analogue, but it is not agent-specific.

### 5. Recommended combined setup (assumed design; built from verified parts and not tested end-to-end)

1. **`.claude/skills/remedy-design/SKILL.md`** (`disable-model-invocation: true`, invoked as `/remedy-design <incident>`), with these template sections in order:
   - Incident facts with transcript turn IDs
   - Causes
   - Built-in inventory per cause
   - Options O0 do nothing / O1 remove / O2 built-in only / O3+ custom
   - Replay matrix (incident turns × options; real prompts × options)
   - Escape-path table
   - Interaction inventory (hooks, plugins, Stop hooks, gates, prompts per task)
   - Failure mode (fail-closed? timeout?)
   - Cost/side effects
   - Rejected-designs check (from `docs/decisions/`)
   - VERIFIED/ASSUMED tags
   - Decision written as an ADR
2. **Replay script** (`scripts/replay-guardrails.sh`): extract `tool_input` payloads of the incident turns from the transcript JSONL and the owner's prompts, pipe each into every proposed hook, and record the exit codes. The skill requires the output file to be attached.
3. **`red-team-remedy` subagent** (tools: Read, Grep, Glob, Bash for running the replay only; fresh context). Prompt: attack the design against the incident and the escape-path list; verify each built-in alternative; flag only gaps that affect whether the incident would recur; also propose deletions. This counters the documented over-engineering drift.
4. **Enforcement of the process itself.** Hook/settings edits already hit protected paths (`.claude`), which prompt in default/acceptEdits/auto, so the human approval point exists without a custom hook.\[8\] Optionally add a fail-closed `PreToolUse` on Edit|Write to `.claude/hooks/**` that checks that a decision file with a replay report exists (with `onFailure: "block"`). Note that this is itself a new stacked gate, so run it through the same template.
5. **Prefer built-ins in the result.** Use `ask` rules for confirmations, the sandbox for file/network boundaries, and auto-mode `environment`/`soft_deny` for intent-level risks, plus `claude auto-mode critique` on any custom rule.\[20\]

## Caveats
- Several features are very new (`onFailure: "block"` Oct 8 2026; `/doctor prompt-audit` v2.1.283; plan-mode behavior changed across v2.1.212–2.1.270).\[22\] Verify against your installed version.
- Protected-path and plan-mode details come from a subagent's extraction of official docs. The sandbox's protected list was only partly visible.
- Community artifacts were assessed from READMEs/listings, not by running them; maturity labels are judgments.
- Anthropic's classifier numbers are vendor-stated,\[44\] on small sets (n=52 for overeager actions).
- The recommended setup is a synthesis and has not been tested as a whole. Its own gate adds stacking and approval cost, which is the very trade-off R11 asks you to weigh.

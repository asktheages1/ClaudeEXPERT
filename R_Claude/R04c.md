# R04 — Changes neither verified as a whole nor propagated: countermeasures for Claude Code (2025–2026)

R04 can only be reliably reduced by moving checks out of the model's goodwill and into deterministic machinery. In practice that means four things. Block scripted shell edits so every document change goes through Edit/Write. Keep each fact in one machine-readable source and generate or verify the derived copies (Plan.md, PROGRESS, backups). Hold a registry of accepted fixes and must-keep rules that a script checks on every version. Gate the end of each turn with a Stop hook that runs a consistency validator (dangling references, counts, version names, registry coverage), plus a fresh-context reviewer subagent for semantic drift. CLAUDE.md instructions alone are advisory and will not hold; Anthropic's own docs say so explicitly.\[1\]

## TL;DR
- **Enforce, don't instruct.** Anthropic's own docs call CLAUDE.md "advisory" and hooks "deterministic". Use a PreToolUse hook that denies `sed -i`/`perl -pi`/heredoc/`python open(...,'w')` writes to `*.md` (ready-made: file-tools-first, claude-no-shell-edits, claude-code-bash-write-guard, cc-safe-setup). Add a Stop hook that runs a docs validator and blocks the turn until it passes.
- **One source of truth plus a regression registry.** Anthropic's long-running-agent harness (Justin Young, "Effective harnesses for long-running agents", Anthropic Engineering, 26 Nov 2025) keeps state in a JSON feature list of "over 200 features", because "the model is less likely to inappropriately change or overwrite JSON files compared to Markdown files". Apply the same idea here: put facts, accepted fixes, caveats and rules in a structured registry with IDs. Have a script check that every ID still appears in v(n+1), in Plan.md and in the report.
- **Verify the whole, in a fresh context.** Anthropic recommends a reviewer subagent that sees "only the diff and the criteria",\[1\] and OpenAI's Codex team runs linters plus a recurring "doc-gardening" agent. For R04, pair a deterministic validator (links, "section X" references, counts, version names) with a coverage-audit subagent that checks no caveat was lost in condensation.

## Key Findings

1. **Some official mechanisms are hard boundaries and some are not (verified).**
   - Permission rules "are enforced by Claude Code, not by the model". "Instructions in your prompt or CLAUDE.md shape what Claude tries to do, but they don't change what Claude Code allows" (Permissions docs).\[2\]
   - Read and Edit deny rules apply to the built-in file tools and to Bash file commands Claude Code recognises (`cat`, `head`, `tail`, `sed`, `tee`). They also cover redirection targets.\[2\]
   - Bash rules are not a security boundary: `/bin/rm` or `bash -c '…'` forms are not matched. Inline Python/Node scripts that open files themselves are not covered either.\[2\]\[3\]
2. **The Edit tool's read check is weaker than R04 assumes (verified, version-specific).**
   - Per the official tools reference, a read cut short with a `PARTIAL view` notice doesn't count as a read. An explicit `offset`/`limit` read does satisfy the check, so reading lines 100–195 legally unlocks editing that file.\[4\]\[5\]
   - Since v2.1.208, newer models "can edit an unread file when reading it wouldn't need a permission prompt". Since v2.1.228 the same applies to Write.\[5\]
   - Viewing a file with `cat`, `head`, `tail`, `sed -n 'X,Yp'` or `grep` also counts as a read.\[5\]
   - Bash writes (`sed -i`, Python) bypass the check entirely. Checkpointing "does not track files modified by Bash commands", so `/rewind` cannot undo them.\[6\]
   - **Consequence:** nothing built in forces a whole-document re-read. You must add it.
3. **Write tool overwrites are a direct R04 regression vector (verified via issues).** Users report that Write silently dropped content from backup files (issue #27137).\[7\] Another report says Write overwrote an append-only log after Claude "read only the first 15 lines" (#98967).\[8\] The community plugin overwrite-guard reproduced "295 of 300 lines lost in one call" on v2.1.281.\[9\]
4. **Anthropic's internal practice relies on structured state, not prose (verified).**
   - The "Effective harnesses for long-running agents" post (Justin Young, Anthropic Engineering, 26 Nov 2025) uses `feature_list.json` and `claude-progress.txt` and lets agents change only a `passes` field. It uses wording like "It is unacceptable to remove or edit tests".
   - The "How Anthropic teams use Claude Code" report describes end-of-session documentation updates and frequent commit checkpoints.\[10\]
5. **OpenAI's Codex team handles the exact R04 failure class mechanically (verified).** "Dedicated linters and CI jobs validate that the knowledge base is up to date, cross-linked, and structured correctly". A recurring "doc-gardening" agent "scans for stale or obsolete documentation that does not reflect the real code behavior and opens fix-up pull requests", and AGENTS.md acts as a table of contents rather than an encyclopedia.
6. **Condensation loses caveats predictably (verified, research).** Lee et al. ("When Summaries Distort Decisions", arXiv 2606.29251, June 2026) call this "decontextualization": "compression often keeps headline results while dropping the caveats, offsets, comparisons, and forward-looking qualifiers needed to interpret them". On the Gavel legal-summarisation benchmark (Dou, Mamut & Xu, arXiv 2601.04424), the top model out of 12 tested, Gemini 2.5 Pro, scored 59.1 F1 with 55.3 recall on checklist items; the authors conclude that "current models are more prone to omitting key information than hallucinating". Processing documents chunk by chunk and iteratively extracting checklist items raised recall "by 28 points on average compared to top LLMs' summaries". The practical answer is a checklist-driven coverage audit, not "summarise carefully".
7. **No official mechanism exists** for these sub-aspects:
   - a document dependency index or change propagation between Markdown files
   - transclusion inside Claude Code
   - an accepted-fixes or invariants registry
   - a cross-reference ("see section 7") validator
   - version-name consistency checks
   - a forced full-file re-read

   All of these must be built from hooks, scripts and subagents.

## 1. Official recommendations and mechanisms (Anthropic)

| Mechanism | What it gives you for R04 | Enforcement | Notes / version |
|---|---|---|---|
| **PreToolUse hook** (`permissionDecision: "deny"`, or exit 2) | Inspect Bash command text and deny scripted writes to docs, pointing Claude to Edit. Also gate Read calls with `offset`/`limit` on report files, or gate Edit until a full read is logged (custom). | Deterministic | `if` field uses permission syntax, but "Because the `if` filter is best-effort, use the permission system rather than a hook to enforce a hard allow or deny".\[11\] `onFailure: "block"` (v2.1.295+) makes a crashing hook fail closed.\[11\] |
| **permissions.deny** e.g. `Bash(sed -i *)`, `Edit(./reports/**)` with ask | Blocks the common `sed -i` form. Edit deny rules also cover `sed`/`tee`/redirection targets. | Deterministic but bypassable (`python -c`, `/usr/bin/sed`, `bash -c`) | Rules are evaluated deny → ask → allow, and an allow can't carve an exception out of a deny.\[2\] |
| **PostToolUse hook** on `Edit\|Write` | After every doc edit, run the validator and feed results back via `hookSpecificOutput.additionalContext` or `decision: "block"`. | Deterministic trigger | Plain stdout from PostToolUse does not reach Claude; you must emit JSON or exit 2 (community finding, harness-kit #137).\[12\] |
| **Stop / SubagentStop hook** (`decision: "block"`) | "A Stop hook runs your check as a script and blocks the turn from ending until it passes" (best-practices).\[1\] This is the main gate for whole-document consistency. | Deterministic | Claude Code overrides a Stop hook after 8 consecutive blocks with no tool call; raise with `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`. Check `stop_hook_active` to avoid loops.\[13\] |
| **Prompt / agent hooks** (`type: "prompt"` / `"agent"`) | A Stop-time verifier with Read/Grep access that checks the registry against the report semantically. | Model judgement on a deterministic trigger | Agent hooks are "experimental and may change".\[11\] |
| **FileChanged / InstructionsLoaded / PostToolBatch events** | FileChanged watches literal filenames (e.g. `Plan.md`) and can trigger re-validation when a file changes on disk, including Bash writes. | Deterministic trigger | Listed in the current hooks reference.\[11\] |
| **Verification subagent / `/code-review`** | "A reviewer running in a fresh subagent context sees only the diff and the criteria you give it."\[1\] It catches regressions the author can't see. | Advisory unless wired into a Stop hook | Best-practices "Add an adversarial review step".\[1\] |
| **`/goal`** | A session-scoped, prompt-based Stop condition,\[11\] e.g. "validator passes and registry coverage = 100%". | Model-evaluated | Built-in shortcut.\[11\] |
| **CLAUDE.md + `@path` imports + `.claude/rules/`** | Put rules in one file and import them into others: transclusion for instructions only, not for report content. | Advisory | "Unlike CLAUDE.md instructions which are advisory, hooks are deterministic". Bloated files cause ignored rules.\[1\] |
| **Skills** (`.claude/skills/*/SKILL.md`, with frontmatter hooks) | A packaged workflow such as `/release-report`: regenerate derived docs, run the validator, run the coverage audit. | Advisory invocation; hooks inside are deterministic | Skill-frontmatter hooks support `once`.\[11\] |
| **Checkpointing / `/rewind`** | Undo edits made by file tools only.\[14\] | n/a | Doesn't track Bash writes,\[6\] which is another reason to ban them. |
| **Read tool PARTIAL view** | A truncated whole-file read doesn't unlock Edit.\[4\] | Deterministic | v2.1.145+. A `PARTIAL view` read doesn't count; an offset/limit read does.\[4\]\[15\] |

**Explicitly no official mechanism:** an inter-document dependency index; propagation of a fact to all copies; a must-keep/accepted-fix registry; a "see section X" or "table H2" reference validator; version-name normalisation; forced full re-read before edit. (Only the PARTIAL-view rule exists, and it is relaxed for newer models.)

## 2. How the biggest players solve it

- **Anthropic (long-running harness).**
  - An initializer agent writes a JSON feature list in which everything starts as failing. Coding agents may only flip the `passes` field.\[16\]\[17\]
  - Progress lives in `claude-progress.txt` plus git commits.\[17\]
  - Every session starts by reading the progress file, the feature list and the git log.\[16\]
  - Transfer to R04: make `decisions.json` / `invariants.json` the source of truth and treat the Markdown reports as derived.
- **Anthropic (internal teams).**
  - Teams report end-of-session documentation updates and starting from a clean git state with frequent checkpoint commits, so they can revert when Claude drifts.\[10\]
  - Security Engineering consolidates multiple sources into Markdown runbooks.\[18\]
  - Transfer: commit each report version, then diff v(n) against v(n+1) and review removed lines explicitly.
- **Anthropic (docs guidance).** Use a second-opinion verifier so "the agent doing the work isn't the one grading it". Show evidence (command output) instead of asserting success.\[1\]
- **OpenAI Codex (harness engineering).**
  - The `docs/` directory is the system of record, with a short AGENTS.md ("roughly 100 lines") serving "primarily as a map" — "we treat it as the table of contents".
  - Linters and CI check that docs are fresh and cross-linked.\[19\]
  - A recurring "doc-gardening" agent "scans for stale or obsolete documentation that does not reflect the real code behavior and opens fix-up pull requests".
  - Lint error messages include remediation instructions for the agent.\[20\]
  - This transfers directly to Claude Code through hooks and CI.
- **Docs-as-code practice (any team).** Generate derived sections from source with markdown-magic (comment-block transforms) or embedme (`--verify` fails if embedding would change the file). MultiMarkdown `{{file}}` transclusion and mkdocs-autorefs give stable cross-references.\[21\]\[22\]\[23\]\[24\]

## 4. Recommended stack for R04 (design — assembled from verified primitives; not a published product)

1. **Ban scripted doc edits.** Install file-tools-first or bash-write-guard, scoped to `*.md` in the reports/plan directories. Add `permissions.deny` entries for `Bash(sed -i *)` and `Bash(perl -pi *)` as a second layer. Set `onFailure: "block"`.
2. **Force full reads before edits (custom).**
   - A PostToolUse hook on Read logs `file_path` to `.claude/state/fullread.txt` only when there is no `offset`/`limit` and no PARTIAL view.
   - A PreToolUse hook on `Edit|Write` for report files denies the edit unless the path is logged and the file's mtime/hash is unchanged since that read. The deny message is "Read the whole file first".
   - Optionally deny `Read` with `offset` on files under a size threshold.
3. **Keep one source of truth.**
   - Put the shared facts (scope, single-repo caveat, CRLF exception, clean-tree definition, byte-for-byte rule, version name, counts) in `facts.yaml` or JSON, each with an ID.
   - Generate Plan.md/PROGRESS/backup sections with markdown-magic blocks, or check them with embedme `--verify`-style diffs. Never hand-edit generated blocks.
4. **Keep an accepted-fixes and invariants registry.**
   - `decisions.json` lists each accepted fix with its ID, a canonical phrase or regex, the files it must appear in, and its status (active / withdrawn / superseded).
   - The validator fails if an active item is missing from any required file, or if a withdrawn statement's phrase still appears anywhere. This covers the "withdrawn in one file, still standing in the report" symptom.
5. **Run a validator script from PostToolUse and Stop hooks.** It checks:
   - Markdown links and anchors (lychee).
   - Regexes for `sekcja \d+|section \d+|tabela [A-Z]\d+|patrz …|Plan.md condition` (Polish: "sekcja" = section, "tabela" = table, "patrz" = see) resolved against actual headings and table IDs.
   - A single allowed version-name pattern.
   - Counts recomputed from source.
   - PROGRESS/headers timestamps not older than the newest report.
6. **Run a coverage-audit subagent for condensation.** It is read-only, gets the source report plus the condensed Plan.md, and extracts every rule, caveat and exception into a checklist, chunked by section (this follows the Gavel finding).\[43\] It reports each item as present, absent or weakened. Wire it in as a Stop-time `type: "agent"` hook or a `/condense` skill step.
7. **Run a version regression diff.** Commit each version. A script lists lines and registry IDs removed between v(n) and v(n+1), and a reviewer subagent must justify each removal.
8. **Add a dependency index.** `docs-index.yaml` maps each fact ID to the documents and sections that contain it. A PostToolUse hook on an edited file injects `additionalContext` naming every dependent doc that must be updated. The Stop hook verifies the update.
9. **Keep CLAUDE.md short (advisory layer).** Include: "never rewrite a report from an older version — edit the latest"; "condensation must preserve every registry ID"; and a pointer to the registry and the validator command.

## Symptom → countermeasure map

| R04 symptom / mechanism | Primary countermeasure | Backup |
|---|---|---|
| Scripted fragment-replacing edits after a slice read; never re-read in full | PreToolUse shell-write block (file-tools-first etc.) + full-read ledger hook | overwrite-guard; reviewer subagent reads whole file |
| Edit read-check bypass (O0:97, O0:24) | Same; note the check itself is relaxed for newer models (v2.1.208+)\[5\] | `permissions.deny` for sed/perl in-place |
| v2 fixes lost in v3 (single-repo caveat, CRLF, clean-tree, byte-for-byte) | Accepted-fixes registry + validator; ADR "never revert" rule | v(n)→v(n+1) removed-line diff review |
| Corrected error left in another section (O1 l.51) | Registry "withdrawn/superseded" phrases grep'd across all files | Fresh-context reviewer with the correction list |
| "Withdrawn" statement still in the report | Same | — |
| Plan.md stale vs report and its own justification | Generate Plan.md facts from the source; drift-doc header checks | Stop hook timestamp/ID coverage check |
| PROGRESS / headers / counts / Backup describe non-existent state | Auto-generate status from the registry/git; validator recomputes counts | Stop hook blocks on mismatch |
| Dangling refs ("sekcja 7", "tabela H2", "patrz sekcja 9", "warunek w Plan.md") | Custom reference validator (regex → heading/table ID map), lychee for anchors | Explicit anchors/IDs (mkdocs-autorefs style) |
| Inconsistent version names | One canonical version field in `facts.yaml` + regex lint | — |
| Caveats/rules dropped when condensing | Checklist coverage-audit subagent (chunked) | Registry IDs required in Plan.md |
| Same facts in four documents | Single source + generation/transclusion; dependency index | Propagation reminder via PostToolUse additionalContext |
| Each round rewrites from an earlier version | Commit per version; validator compares against HEAD registry; CLAUDE.md rule | overwrite-guard on Write |

## Effectiveness / effort / limitations

| Method | Enforcement | Effort | Effectiveness | Limitations |
|---|---|---|---|---|
| PreToolUse shell-write block | Deterministic | Low (install plugin) | High for common forms | Regex-based; misses `python script.py`, `git apply`, `dd`\[26\] |
| permissions.deny sed/perl | Deterministic | Very low | Medium | Bypassable by other invocations; adds retries\[2\]\[42\] |
| Full-read ledger hook | Deterministic | Medium (custom) | High | Must handle files that legitimately exceed the 25k-token read limit (page through all pages)\[5\] |
| overwrite-guard | Deterministic | Low | High against Write data loss | Heuristic thresholds (≥10 lines, 5%)\[9\] |
| Single-source + generation | Deterministic | Medium–high (restructure docs) | Very high | Needs discipline to keep generated blocks untouched |
| Accepted-fixes registry + validator | Deterministic | Medium | Very high against regressions | Phrase/regex matching can miss paraphrases, so pair it with a reviewer |
| Reference/version/count validator in Stop hook | Deterministic | Medium | High | Custom regexes per language (PL/EN) |
| Coverage-audit subagent | Model judgement | Low–medium | Medium–high | Non-deterministic; recall drops on long docs, so chunk by section\[43\] |
| Reviewer subagent / `/code-review` | Advisory unless hooked | Low | Medium | May share blind spots; give it explicit criteria |
| Agent/prompt Stop hook | Model judgement, deterministic trigger | Low | Medium | Experimental; 8-block cap\[11\]\[13\] |
| CLAUDE.md rules / ADR instructions | Advisory | Very low | Low–medium | Ignored when the file is long or the context is full\[1\] |

## Caveats
- The read-before-edit rules changed several times during 2026: PARTIAL view in v2.1.145, relaxed unread/changed-file editing in v2.1.208, and the Write rule change in v2.1.228. Behaviour depends on both the Claude Code version and the model (Opus 4.6 and Haiku 4.5 and older still always require the read).\[5\]\[15\] Check `claude --version`.
- Two version attributions come from secondary sources and are not confirmed in official docs: the v2.1.143 date for the Stop-hook block cap, and "0 disables it".\[44\]\[45\]
- Community plugins are small, single-author projects. Review the code before installing. Their claims (e.g. the overwrite-guard reproduction) are self-reported.
- Section 4 is a design assembled from verified primitives; it has not been benchmarked as a whole.

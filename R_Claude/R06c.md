# R06 — Making Claude Code quality gates mandatory, independent, ordered and broad: all known ways to close the gap

You cannot close R06 with CLAUDE.md wording, and no single built-in Claude Code feature closes it either. What does close it is a stack of mechanical controls. Hooks block the irreversible steps (commit, push, PR creation, merge, writing plan files, ending the turn) until a review receipt exists. That receipt can only be written by a separate reviewer that the author does not brief and cannot impersonate. Git hooks, CI required checks and branch protection run outside the agent as a backstop. Anthropic's own documentation says the same thing: "Unlike CLAUDE.md instructions which are advisory, hooks are deterministic and guarantee the action happens". It also recommends Stop hooks and independent verification subagents "so the agent doing the work isn't the one grading it".\[1\]

## TL;DR

- **Root cause → fix:** the review gate was voluntary and run by the author, so make it a mechanism. Use PreToolUse hooks with exit code 2 or `permissionDecision: "deny"`, plus `permissions.deny`/`ask` rules, on `git commit`, `git push`, `gh pr create`/`merge`, `ExitPlanMode` and plan-file writes. Add a Stop hook that won't let the turn end without evidence. Tie each of these to a hash-bound review receipt that only a SubagentStop hook on a dedicated reviewer agent can write.
- **Independence and breadth:** the author must not write the reviewer's brief. A fixed `.claude/agents/reviewer.md` holds a mandatory rubric covering facts, feasibility, alternatives, omissions, design flaws, placeholders and the current turn. A PreToolUse hook on the `Agent` tool injects that rubric through `updatedInput`, and the SubagentStop hook rejects verdicts with missing rubric fields. For repeated rounds, add a reviewer from a different model family or a multi-agent reviewer. Cross-model research and Anthropic's own internal numbers favour these.
- **Hard limits to accept:** Stop hooks fire *after* the chat answer is already on screen (open feature request #97601), so chat-only deliverables can only be gated by routing them through files or by forcing a revision. Hooks can be bypassed (`--no-verify`, MCP commit tools, `disableAllHooks`, timeouts that let the action through), so finish with managed settings, git pre-commit/pre-push hooks running `claude -p` as an outside reviewer, and CI required checks with human approval.

## Key Findings

1. **Official mechanisms are strong enough to make gates mandatory and ordered**, as long as you build them. The hooks reference (current docs, Claude Code v2.1.29x) lists blocking events relevant to R06: `PreToolUse` (blocks the tool call), `Stop` ("Prevents Claude from stopping, continues the conversation"), `SubagentStop`, `TaskCompleted` ("Prevents the task from being marked as completed"), `PostToolBatch`, `UserPromptSubmit` and `ConfigChange`. Only exit code 2, or valid JSON with a block/deny decision, actually blocks. "Claude Code treats exit code 1 as a non-blocking error".\[2\] This is the most common reason home-made gates silently fail open.\[3\]
2. **There is no official "deliver ⇔ checked" link, receipt or token.** Anthropic provides the building blocks (hooks, `last_assistant_message`, `stop_hook_active`, `background_tasks`, `agent_type`, `updatedInput`), but no built-in "review required before commit" setting. The managed **Code Review** product explicitly "won't approve PRs — that's still a human call".\[4\]\[5\]\[6\]
3. **Chat deliverables are the weakest point.** Plans, analyses, translations and recommendations sent in chat cannot be held back before the user sees them: the Stop hook runs after the response is rendered, and the requested "PreResponse"/blocking `MessageDisplay` hook does not exist yet (issue #97601).\[7\] The only mechanical fix is to make delivery a *tool call*, for example writing to `deliverables/` and then a short chat pointer, which PreToolUse can gate.
4. **Separation of author and reviewer is the official recommendation**, not just community folklore. The best-practices page says a fresh-context reviewer "sees only the diff and the criteria you give it".\[1\] Anthropic's harness-design post found "Out of the box, Claude is a poor QA agent" and that separate generator/evaluator agents beat self-evaluation.\[8\] `/goal` uses "a fresh model rather than the one doing the work", but it only judges the transcript and runs no tools of its own.\[9\]
5. **Big players all keep a gate outside the authoring agent.** At GitHub, Copilot's cloud agent "cannot approve or merge a pull request", and "The developer who asked Copilot to create a pull request cannot approve that pull request".\[10\]\[11\] Stripe's Minions open PRs that pass CI and are then human-reviewed; Alistair Gray on the Stripe Dev Blog (Feb 9, 2026) says they are "responsible for more than a thousand pull requests merged each week. Though humans review the code, minions write it from start to finish." Anthropic's Code Review launch post (Claude blog, Mar 9, 2026) says it runs on "nearly every PR": "Before, 16% of PRs got substantive review comments. Now 54% do", with "less than 1% of findings … marked incorrect". Spotify is the cautionary tale. Max Charas and Marc Bruggmann wrote on Spotify Engineering (Dec 9, 2025) that "out of thousands of agent sessions, the judge vetoes about a quarter of them". InfoQ's write-up of a QCon London 2026 talk by Jo Kelly-Fenton and Aleksandar Mitic says Spotify "found it too rigid, blocking valid changes" and removed the judge, and started allowing "migration drivers to approve their own PRs."
6. **Review rounds work better with independence and diversity than with repetition.** Xiang, Zhang, Zhang and Xu (arXiv 2607.21656, Agentic SE @ KDD '26) ran static review only, with no test execution, on 116 hard/medium LiveCodeBench tasks. "Claude Opus 4.7 review raises Codex GPT-5.5 drafts from 71.6% to 89.7%", while "Codex GPT-5.5 reviewing Claude Opus 4.7 drafts drops the pass rate from 91.4% to 82.8%" and "Claude Opus 4.7 self review leaves the 91.4% baseline unchanged." A second pass is not automatically helpful: the reviewer has to be at least as capable as the author and properly briefed.

## Details

### Sub-problem map (used in the tables)

- **S1** Mandatory, not voluntary (including non-code deliverables)
- **S2** Reviewer ≠ author; no "I checked it myself" without evidence
- **S3** Ordering before irreversible steps; waiting for helpers; deliver⇔checked link
- **S4** Breadth of the review brief (alternatives, omissions, design flaws, current turn)
- **S5** Placeholders/TODO/stubs
- **S6** Effective rounds (adversarial, independent, multiple, audit moved earlier)

### Mapping the R06 incidents to mechanisms

- **Report v3/v4, Plan.md, oath, translation, 21:04 recommendation went out unchecked (S1, chat).** Route every deliverable through `deliverables/<id>.md` (the CLAUDE.md rule, plus a Stop hook that blocks any turn whose `last_assistant_message` exceeds N words or matches deliverable markers without a receipt for a file in `deliverables/`). The final chat message must quote the receipt ID. Because Stop fires after display, the user may briefly see unreviewed text. Make that visible: the hook's `reason` forces a "⚠ UNREVIEWED — revision follows" correction.
- **Seven auditors launched after commit and PR #1 (S3).** Use a PreToolUse deny on `git commit`/`git push`/`gh pr create` unless `.claude/gate/receipt-<tree-hash>.json` exists with `verdict: PASS` and a timestamp after the last Edit/Write. The tree hash comes from `git write-tree` on the index, so any later edit invalidates the receipt (C1 does the same thing).
- **Link check ran 14 s after "I checked it myself" (S2).** Add a Stop "claim–evidence" hook. A regex finds claims (`checked|verified|tested|sprawdziłem|zweryfikowałem|all links work` (Polish: "sprawdziłem" = I checked, "zweryfikowałem" = I verified)) in `last_assistant_message`. A PostToolUse logger records every tool call with a timestamp in a state file (don't rely on `transcript_path`, which "may lag").\[2\] If no matching verification command ran *earlier in the current turn*, block with "show the evidence or retract the claim".
- **Plan.md committed before helpers reported (S3).** SubagentStart/SubagentStop hooks increment and decrement `.claude/gate/running`. PreToolUse on Write/Edit of `Plan.md` and on `git commit` denies while running > 0. The Stop hook also blocks while `background_tasks` is non-empty.
- **Placeholders committed as content (S5).** A PreToolUse check on Write/Edit content and a git pre-commit check on the staged diff look for `TODO|TBD|FIXME|XXX|lorem|<placeholder>|\[\.\.\.\]|NotImplementedError|pass  # stub`. A CI grep acts as the final backstop.
- **Verifier briefed only on facts/feasibility (S4).** Use a fixed reviewer agent with a mandatory rubric. A PreToolUse `Agent` hook appends the rubric through `updatedInput` (or denies a reviewer call whose prompt lacks the rubric). The SubagentStop hook rejects a verdict JSON that is missing any of: `facts`, `feasibility`, `alternatives_considered`, `omissions`, `design_flaws`, `scope_vs_request`, `placeholders`, `current_turn_reviewed`, `evidence`.
- **No helper examined the current turn (S4).** The rubric field `current_turn_reviewed` requires quoting the current turn's deliverable or its hash. The Stop gate applies to every turn that produced a deliverable, not only to commits.
- **Errors survived two rounds; found only by the pre-merge audit (S6).** Move that audit to *pre-commit/pre-PR* (C1/C2 pattern). Use a different-model or multi-lens reviewer (C3, C5, A18) and a fresh context each round. Give the reviewer the previous round's findings with the instruction "find what they missed". Escalate to a human after 2 failed rounds instead of looping.

### Reference design: the review-receipt protocol (my synthesis; assembled from documented primitives, not an official feature)

1. `.claude/agents/reviewer.md`: `tools: Read, Grep, Glob, Bash(git diff*)`, no Write. The prompt holds the full rubric and demands a final JSON verdict.
2. PreToolUse `matcher: "Agent"`: if `subagent_type == reviewer`, inject the rubric and the artifact hash (`updatedInput`). If the author tries to "review" with a general-purpose agent instead, deny.
3. SubagentStop `matcher: "reviewer"` (command hook): parse the verdict, exit 2 if any rubric field is missing or empty. Otherwise the *hook itself* writes `.claude/gate/receipts/<hash>.json`. The author never writes receipts. Back this with `permissions.deny: ["Edit(.claude/gate/**)", "Write(.claude/gate/**)"]` and sandbox write-deny for Bash.
4. PreToolUse gates on commit, push, PR, merge, ExitPlanMode and plan/deliverable writes, all requiring a matching receipt; `onFailure: "block"`.
5. Stop gate: helpers still running, claims without evidence, deliverable without receipt, or placeholders → block, with a `stop_hook_active` check and a per-reason marker so it cannot loop forever.
6. Outside the agent: git pre-commit/pre-push run `claude -p` with the reviewer prompt and the same placeholder scan, plus a `--no-verify` blocker. CI runs the same checks as **required status checks**, and branch protection requires a human approval that is not the requester's.

## Recommendations — layered setup, ranked by how much each closes R06

1. **CI required checks + branch protection + human approval (no self-approval).** This is the only layer the agent cannot touch. It covers S3 and S6 for code. It does not cover chat deliverables.
2. **PreToolUse receipt gates on irreversible steps (commit/push/PR/merge/ExitPlanMode/plan writes) with `onFailure: "block"`, plus permissions `deny`/`ask` backstops.** This is the core fix for "gate after the irreversible step" (S1, S3).
3. **Separate reviewer agent + SubagentStop-written receipts + rubric injection (`updatedInput`).** Fixes "author runs and briefs its own gate" (S2, S4).
4. **Stop hook: helper-wait, claim–evidence, deliverable-must-have-receipt, placeholder scan.** Covers non-code deliverables and "I checked it myself" (S1, S2, S5). It is limited by post-display timing.
5. **Different-model/multi-lens adversarial reviewer at pre-commit (C1/C2/C3), with the pre-merge audit moved earlier.** Fixes errors surviving rounds (S6).
6. **Managed settings (`allowManagedHooksOnly`, deny editing `.claude/settings*.json`, ConfigChange block) + `--no-verify` blocker + git hooks with `claude -p`.** Makes layers 2–5 hard to switch off.
7. **Design the step order up front:** `TaskCreated` hook rejects plans without review tasks, and `TaskCompleted` blocks "done" without a receipt. A sprint contract (B3) sets acceptance criteria before work starts.
8. **Advisory last:** CLAUDE.md rule text, superpowers skills, `/goal`. Keep them for guidance and phrasing, never as the gate.

Roll-out order: start with 2 and 4 (one afternoon, shell + jq), then 3, then 1 and 6, then 5. Calibrate the reviewer so it flags only correctness/requirement gaps (official caution; Spotify's experience) and cap automatic rounds at 2 before escalating to the human owner.

## Caveats

- **Verified vs assumed.** Event semantics, exit codes, `onFailure`, the 8-continuation cap, `background_tasks`, `last_assistant_message`, ExitPlanMode input and the timeout behaviour come from the current official hooks reference. Three pieces are my own design and need a test in your version: the receipt protocol, rubric injection via `updatedInput` on the `Agent` tool, and the claim–evidence detector. Agent hooks are officially "experimental".\[2\]
- **Version-specific:** `onFailure` needs v2.1.295+, `/goal` v2.1.139+, the 8-block cap reportedly since v2.1.143,\[13\]\[20\] project-subagent frontmatter hooks need trust (v2.1.218+), and `if` path semantics changed in v2.1.214. Prompt-based SubagentStop failed to block in v2.1.17 (#20221).\[16\]
- **Bypasses remain:** Bash can write files that Edit/Write deny rules protect unless the sandbox blocks it. Regex `if`/deny patterns miss command variants. A model can game transcript-string gates (e.g., by printing "APPROVE"). Stop gates cannot un-show text. LLM reviewers produce false positives, and over-strict gates get disabled, as at Spotify.
- **Vendor numbers** (Anthropic 16%→54%, <1% incorrect; Stripe volumes; Spotify veto rate) are self-reported and unaudited. The Spotify judge removal comes from InfoQ's write-up of the QCon London 2026 talk. The GitHub change ("Copilot code review can now approve pull requests", Sept 1, 2026, off by default, admin-enabled) comes from DevOps.com and daily.dev reports, not from the GitHub changelog itself.

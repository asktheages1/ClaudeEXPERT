# R02 – Enforcing source reading before verdicts in Claude Code (EN)

As of: October 13, 2026

**Direct answer:** Claude Code has no official mechanism that forces the model to read the governing source before giving a verdict. A verdict is text, not a tool call, so neither a permission rule nor the built-in "Read before Edit" check can intercept it. The only way to get close is to assemble your own "evidence-before-verdict" gate from official building blocks: a read log (PostToolUse hook on Read), blocking the end of a turn or the exit from plan mode (Stop and ExitPlanMode hooks), and automatic quote verification (a command or agent hook). Add to that redirecting shell reads to the Read tool and injecting key rules at decision time. CLAUDE.md instructions, skills and plan mode help, but they are soft steering. Issues in anthropics/claude-code show it fails in exactly the situations described here.

## TL;DR

- **Hard enforcement exists only for tool calls, not for response content.** PreToolUse, PermissionRequest and Stop hooks can block; Stop can also force the model to keep working. Build your own gate from them: "verdict or plan without a read source, or with a quote that does not match the file, means a block". No ready-made gate of this kind was found. The closest are Cupcake's `claude_code_enforce_full_file_read` rule and the `track_reads.py` read logger (opsmill/infrahub, PR #10713).
- **Partial reads have three sources, and each needs its own countermeasure.** (1) The Read tool truncates output: 25,000-token limit, files over 256 KB are rejected, a "PARTIAL view" notice appears. (2) The model picks a fragment itself: `offset`/`limit`, `head`, `cut`, `sed -n`. (3) Long Bash output is replaced by a file plus a 2,000-character preview. For (2) and (3): a PreToolUse hook on Bash (deny and redirect to Read) and rewriting Read arguments via `updatedInput`. For (1): the `allow_large` setting / `CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS` and a line-coverage check.
- **Recommended set** (layers from hardest):
    1. hooks: read log, denial of shell reads, gate on ExitPlanMode and Stop;
    2. an agent hook or subagent verifying quotes in the form "file:line + verbatim quote ±2 lines";
    3. routing questions about Claude Code to the `claude-code-guide` subagent or a local docs mirror;
    4. a short CLAUDE.md with a "quote-first" rule per Anthropic's official guidelines.

## 1. Diagnosis in terms of Claude Code mechanisms (confirmed by sources)

Each symptom is a shortcut while reading or a verdict made with no tool call at all.

| Symptom from the problem description | Claude Code mechanism that enables it | Source |
| --- | --- | --- |
| The Edit read check covers only the edited file (O0:24) | "Read-before-edit" applies to the edited file. Bash commands from the Tools reference list also count as a read: "cat, nl, bat, batcat, head, tail, sed -n 'X,Yp', grep, egrep, fgrep, and rg, each run on one file with no pipes or redirects". Per Tools reference, "Claude Opus 4.6, Claude Haiku 4.5, and older models always require the read"; newer models (from v2.1.208) may edit an unread file if reading it would not need approval and the Read tool is available. | "I read SKILL.md" after 80 of 120 lines | The model chooses to sample on its own (#28743, #2595). After compaction it switches to grep/wc/partial reads (#7533) | [#7533](https://github.com/anthropics/claude-code/issues/7533) |

**Conclusion (my interpretation):** the gate must sit where the verdict is emitted: in the Stop hook (end of turn) and in ExitPlanMode (plan approval). Edit tools are too late.

## 2. Official mechanisms and recommendations (Anthropic documentation)

Legend: **HARD** = deterministic, enforced by the harness. **SOFT** = an instruction to the model. **NONE** = no official mechanism.

### 2.1 Hooks (the key tool for R02)

Sources: [Hooks reference](https://code.claude.com/docs/en/hooks) and [Hooks guide](https://code.claude.com/docs/en/hooks-guide).

- **PreToolUse** (HARD): blocks a call via `permissionDecision: "deny"` or exit 2 (stderr goes to Claude). Through `updatedInput` it can **rewrite tool arguments**, e.g. drop `offset`/`limit` from Read for files under N lines, or widen the range by ±20 lines. This addresses "l.345 without l.344". An inference from the docs, not a ready recipe.
- **PostToolUse on Read** (HARD as logging): writes `file_path`, `offset`, `limit` to a session log. The `additionalContext` field (10,000-character limit) adds a note next to the result, e.g. "lines 1–80 of 120 read; this is NOT the full file".
- **Stop / SubagentStop** (HARD): `decision: "block"` with a `reason` prevents the turn from ending. The hook receives `last_assistant_message`, so it can search the text for verdicts ("I reject", "not possible", "auto does not ask", "unprotected") and check whether the read log contains the source. The docs warn that `transcript_path` "may lag"; for the current turn use `last_assistant_message`.
- **`prompt` and `agent` hooks:** an `agent` hook can "spawn a subagent that can use tools like Read, Grep, and Glob to verify conditions before returning a decision". Status: experimental. This is the official basis for a **quote verifier in Stop** that opens the file and checks whether the line says what the answer claims. A `prompt` hook sees only the transcript, not files.
- **UserPromptSubmit / SessionStart / PreToolUse with `additionalContext`** (hard injection, soft application): re-supplying key facts, e.g. "O0:94: auto mode …; O0:102: .claude/ …", with every prompt or before ExitPlanMode. The docs advise writing these as factual statements, not system commands, or they may trigger prompt-injection defences.
- **`onFailure: "block"`** (v2.1.295+): a broken hook does not let the action through. Without it, a typo in a path silently disables the gate.
- **Hooks in skill and subagent frontmatter:** the gate can be attached to a specific workflow, e.g. a "permissions-verdict" skill.
- **InstructionsLoaded:** logs which CLAUDE.md files and rules were actually loaded. Does not block.
- **Limitations:**
    - The `if` field is "best-effort". Docs: "use the permission system rather than a hook to enforce a hard allow or deny".
    - Consecutive Stop blocks are capped. The official [Hooks reference](https://code.claude.com/docs/en/hooks) states: "Claude Code applies an 8-consecutive-continuation cap: after stop hooks have continued the turn eight times in a row, Claude Code overrides the next block and ends the turn. The count of consecutive continuations resets each time Claude calls a tool." The cap is raised with `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`.
    - Files referenced with `@` are not loaded by a tool, so a Read hook will not see them (finding of the research subagent).

### 2.2 Permissions / deny rules

Source: [Permissions](https://code.claude.com/docs/en/permissions).

- `Bash(head *)`, `Bash(tail *)`, `Bash(cut *)`, `Bash(sed -n *)` in `permissions.deny` (HARD, but leaky). Bash rules match command text after compound commands are split and are not a security boundary: a different spelling of the same program will not match.
- Deny rules for Read/Edit also cover `cat`, `head`, `tail`, `sed`, `tee` in Bash, but **only for specific paths**. They block; they do not enforce a full read.
- A rule "read X before a verdict": **NONE** in the permission system.

### 2.3 The Read tool: limits and truncation detection

Source: [Tools reference](https://code.claude.com/docs/en/tools-reference).

- One call returns at most 25,000 tokens (`CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS`). Files over 256 KB are rejected.
- From v2.1.296, `allow_large: true` reads the whole file in one call, with a budget based on free context space.
- A truncated whole-file read returns the first page and a `PARTIAL view` notice. Per #77489 in anthropics/claude-code, the notice was introduced in 2.1.145 instead of a hard error, in the form e.g. "showing lines 1-754 of 3000 total (84502 tokens, cap 25000)". A read with `offset`/`limit` over the limit ends in an error.
- **Known failures:**
    - #28783: a truncated preview treated as the whole file. The author calls the workaround via a rule in `.claude/rules/` "inherently fragile".
    - #6910 and #92979: the 2,000-line default is not applied consistently.
    - #2595 ("Need a way to enforce entire file reading"): closed as not planned. Quote: "Updating CLAUDE.md not reliable".
- Full file coverage: **NONE** officially. Must be done by a hook that sums ranges from the log and compares with `wc -l`.

### 2.4 Plan mode and the "explore → plan → code" workflow

Source: [Best practices](https://code.claude.com/docs/en/best-practices).

- Four phases are officially recommended: Explore (in plan mode "Claude reads files and answers questions without making changes"), Plan, Implement, Commit. SOFT regarding "what to read", though plan mode hard-blocks edits.
- Gate on plan approval: a hook on `ExitPlanMode`. The docs show an `ExitPlanMode` matcher for PermissionRequest (auto-approve); the community also uses it to block (exit 2). For PreToolUse the sources conflict: the older #21282 reported that PreToolUse/PostToolUse do not fire for ExitPlanMode, while newer reports (HN, #46517) show blocking via exit 2. Per #46517, `allow` does not bypass the approval prompt. Test this on your version before relying on it.
- A requirement that the plan enumerate options from the source rather than confirm the chosen approach: **NONE** officially. It can be enforced with an ExitPlanMode hook that checks the plan file for a "Sources" section with line numbers.

### 2.5 CLAUDE.md / memory / rules

- Official advice: a concise CLAUDE.md. Quotes: "Bloated CLAUDE.md files cause Claude to ignore your actual instructions!" and "If Claude keeps skipping one instruction, add emphasis such as "IMPORTANT" to that line alone". Move mandatory things to hooks: "Unlike CLAUDE.md instructions which are advisory, hooks are deterministic".
- CLAUDE.md can also state what must survive compaction, e.g. "When compacting, always preserve …". This is the right place for the list of governing sources and the decision log.

### 2.6 Subagents, verification and "second opinion"

- The built-in `claude-code-guide` (Haiku model) answers questions about Claude Code features from the official docs: [Subagents](https://code.claude.com/docs/en/sub-agents). Invocation is SOFT. It can be enforced with a deny rule on WebFetch/curl to the docs in the main thread, or a UserPromptSubmit hook with a reminder.
- Best practices: "Have Claude show evidence rather than asserting success". An "adversarial review step" in a fresh context is recommended, with a warning that a reviewer set on finding gaps will always find some. Listed hard options: `/goal` (a separate evaluator after each turn) and a Stop hook.
- Claude Code documentation is available as markdown with an index at `https://code.claude.com/docs/llms.txt` (header of every page). It can be downloaded to a file and read in full with Read instead of relying on lossy WebFetch.

### 2.7 Anthropic guidance on quoting (long context / hallucinations)

- [Reduce hallucinations](https://docs.claude.com/en/docs/test-and-evaluate/strengthen-guardrails/reduce-hallucinations): for documents over 20K tokens, "extract word-for-word quotes first before performing its task". Plus "Verify with citations… If it can't find a quote, it must retract the claim" and permission to say "I don't know".
- [Long context tips](https://docs.anthropic.com/en/docs/long-context-window-tips): document at the top, question at the end ("up to 30%" improvement), "Ground responses in quotes".
- [Prompting for long context](https://anthropic.com/news/prompting-long-context): "Pulling relevant quotes into the scratchpad is helpful in all head-to-head comparisons".
- The API Citations feature (sentence-level citations) as a Claude Code tool: **NONE**. What remains is prompting plus hook-based verification.

### 2.8 Output styles

An output style can impose the response format "Verdict → Source (file:line) → Verbatim quote ±2 lines → Options from the source". SOFT: nobody enforces the format, but it gives a stable pattern a Stop hook can parse (inference).

## 3. How the biggest players do it (Anthropic and large teams)

No published mechanism forces reading docs before a verdict; the common thread is verification loops and fresh-context review.

- **Anthropic, "Effective context engineering for AI agents"** ([link](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)): the "just-in-time" approach keeps lightweight identifiers (paths) and loads data with tools when needed. CLAUDE.md is "naively dropped into context up front". For R02 this means the governing source must be loaded right before the decision, not relied on from a read 11 minutes earlier. Other techniques described: structured notes (a decision file) and subagents with separate context.
- **Anthropic, "How Anthropic teams use Claude Code"** ([link](https://www.anthropic.com/news/how-anthropic-teams-use-claude-code), PDF): recurring themes are a detailed CLAUDE.md, self-verification loops ("verify its own work by running builds, tests, and lints") and treating Claude as an iteration partner. There is no mention of a mechanism forcing documentation reads before a verdict. Conclusion: the practice is either unpublished or does not exist.
- **Boris Cherny (creator of Claude Code)**, in his own post as @bcherny on X, January 2026 (tip 13/): "give Claude a way to verify its work. If Claude has that feedback loop, it will 2-3x the quality of the final result". In tip 12/ he advises: "use an agent Stop hook to do that more deterministically". The cleanest place for such a loop is therefore the Stop hook.
- **Maintainer reply in #73281** (per the research subagent): a `PARTIAL view` read "intentionally doesn't count as having read the file", and read-before-edit "has also been relaxed for newer Claude models". The built-in check is weakening, so you need your own.
- **Writer/Reviewer pattern** in the official best practices: a separate session reviews in a fresh context, "since Claude won't be biased toward code it just wrote". The same applies to verdicts: the verifier does not know the author's reasoning.

## 5. Design of the "evidence-before-verdict" gate (inference; no ready-made solution found)

The layout below is built from official building blocks. Each element can be deployed on its own.

1. **`read-log` (PostToolUse, matcher `Read`).** Appends `{file, offset, limit, total_lines}` to `$CLAUDE_PROJECT_DIR/.claude/state/reads-<session_id>.jsonl`. When coverage is below 100%, returns `additionalContext`: "Lines A–B of N read. This is NOT the full file." Directly addresses "80 of 120 lines".
2. **`read-widen` (PreToolUse, matcher `Read`).** When the file has fewer than ~1,500 lines and is on the governing-sources list, `updatedInput` removes `offset`/`limit`. For larger files it widens the range by ±30 lines. Addresses "l.345 without l.344".
3. **`no-shell-peek` (PreToolUse, matcher `Bash|PowerShell`).** Denies when any pipeline segment is `head`, `tail`, `cut`, `sed -n`, `awk 'NR`, `less` or `cat … |` on a text or documentation file. Message: "Use Read without offset/limit (or allow_large)." Exception only for logs, via path or an unlock file with a TTL. Addresses `cut -c1-400`.
4. **`governing-sources.json`.** A map "topic → required files/URLs", e.g. `permissions`: `docs/permissions.md`, `docs/permission-modes.md`, `settings-reference.md`; `app-behaviour`: desktop/web docs plus session metadata. UserPromptSubmit detects topics by keywords and injects `additionalContext`: "Governing sources for this topic: …; a verdict requires quotes from them."
5. **`plan-gate` (PreToolUse or PermissionRequest, matcher `ExitPlanMode`).** Blocks (exit 2) if the required sources are not in `read-log` with full coverage, or the plan lacks the sections "Options enumerated from the source" and "Sources (file:line)". Addresses "plan mode ignored" and reading to confirm a thesis.
6. **`verdict-gate` (Stop, command).** Scans `last_assistant_message` for verdict patterns: rejection, "does not work", "auto does not ask", "unprotected", "v1/v2", "I read". If the detected topic has required sources that are missing from `read-log`, returns `decision: block` with the list of missing files. Check `stop_hook_active` to avoid loops.
7. **`quote-check` (Stop, command or `agent`).**
    - Enforces the quote format `` `file:L344-L346` > "verbatim quote" ``.
    - A script runs `sed -n` on the file and compares the quote after whitespace normalisation. On mismatch it blocks: "the quote does not occur in L344–346". Addresses "O0 §6 does not mention imports".
    - The `agent` variant also reads ±3 lines around the quote and judges whether the context reverses the meaning (e.g. "but/however/except" in the next sentence). Addresses "nudge without its second half".
8. **Decision log (`decisions.md`) + PreCompact/SessionStart(compact).** Key facts from sources, with line numbers, are re-injected after compaction. Addresses "knowledge in context not applied".

**Risks and failure modes:**

- A regex-based verdict detector produces false alarms and misses.
- The model can quote verbatim and still reason wrongly. Only a semantic verifier in `agent` mode helps here.
- Consecutive Stop block cap: per the official Hooks reference, after 8 consecutive continuations Claude Code overrides the block and ends the turn (the counter resets on every tool call; raised with `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`).
- Files referenced with `@` do not reach `read-log`.
- VS Code hooks may not work in some versions (HN report).
- The context cost of full reads, which was the original reason for shortening them.

## 6. Ranking of methods

The strongest single control is a deterministic quote check in the Stop hook; CLAUDE.md rules alone are the weakest.

| # | Method | Enforcement strength | Effort | R02 symptoms addressed |
| --- | --- | --- | --- | --- |
| 1 | Stop `quote-check` (verbatim match of quote vs file) | HARD, deterministic | Medium | wrong citations, selective quoting (partly) |
| 2 | Stop `verdict-gate` + `read-log` + `governing-sources.json` | HARD (depends on heuristics) | Medium–high | verdicts without source, rejected skill, permissions v1/v2 |
| 3 | PreToolUse `no-shell-peek` (Bash/PowerShell) | HARD | Low | `cut`/`head`/`sed -n` |
| 4 | PreToolUse `read-widen` (`updatedInput`) | HARD | Low | l.345 without l.344, 80/120 lines |
| 5 | ExitPlanMode gate | HARD (test on your version) | Low–medium | ignored plan mode, reading to confirm a thesis |
| 6 | Agent hook / verifier subagent (fresh context) | Semi-hard (model judges) | Medium | quote meaning, "nudge" without its second half |
| 7 | `allow_large` / `CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS` | Configuration | Very low | truncation by token limit |
| 8 | Local docs mirror + `claude-code-guide` | SOFT | Low | "Create PR" from git, answers from memory |
| 9 | UserPromptSubmit / PreCompact fact re-injection | Hard injection, soft application | Low | O0:94/102 contradicting the verdict |
| 10 | CLAUDE.md "quote-first, retract if no quote", output style | SOFT | Very low | all (weakly) |
| 11 | Deny rules `Bash(head *)` etc. | HARD, but leaky | Very low | basic shell workarounds |

## 8. Caveats

- **Confirmed vs inferred:**
    - Confirmed in documentation: Read and Bash limits, hook fields (`updatedInput`, `additionalContext`, `last_assistant_message`, `agent` hooks, `onFailure`), the scope of the read-before-edit check, the "quote-first/retract" guidance.
    - Inferred (my design, no existing implementation): the elements in section 5, in particular `verdict-gate`, `quote-check`, `read-widen` and `plan-gate` with the sources-section requirement.
- Version-gated features (e.g. `allow_large` from v2.1.296, `onFailure` from v2.1.295) may be unavailable in older installs.
- Hook behaviour on ExitPlanMode is ambiguous across sources and needs testing.
- Some community resources (sgaabdu4, claude-mem, read-once) were verified only through summaries or search results.
- The hypothesis in the problem description ("memory instead of the source") is consistent with #28743, #7533 and #46588, but these are user reports, not Anthropic measurements.

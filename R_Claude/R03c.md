# R03: Keeping Claude Code Session Evidence Complete, Current, Persistent and Disclosed

The R03 failure comes from one mistake: S1 and S2 were audited from renders instead of the raw record. Claude Code already writes a complete record of every session, the JSONL transcript at `~/.claude/projects/<project>/<session-id>.jsonl` with its `tool-results/` and `subagents/` sibling folders, and the official docs describe it as "every message, tool call, and tool result".\[1\] The fix is to make that file the evidence of record. That means five things: retain it, copy it out at PreCompact/Stop/SessionEnd, commit or push it with a hash manifest, render it only with a disclosure header, and give auditors its path and a snapshot cut-off instead of a summary.

## TL;DR

- **Most of what S2's render dropped is still in the raw JSONL, which is complete but temporary.** Tool calls with their full input (including `run_in_background`), tool results, `permission-mode`/`system`/`compact_boundary` records and queued mid-turn messages are all there, but in non-obvious record types. The file is deleted silently after `cleanupPeriodDays` (default 30). In cloud sessions it lives in a VM that is eventually reclaimed. Every viewer and exporter, including the official `/export`, produces a lossy render.
- **There is no official "evidence mode".** The building blocks do exist: `transcript_path` in every hook payload, a PreCompact hook that can block compaction, SessionEnd/Stop hooks, `--output-format stream-json --verbose`, the SDK SessionStore adapter, OpenTelemetry with an explicit `[TRUNCATED ...]` marker, and a documented file-spill for large tool output. A reliable setup combines them: a hook-driven capture, a git push to an evidence branch, a sha256 manifest, and an auditor subagent restricted to raw paths.
- **Anthropic's published practice is to externalise state into files and git.** Its long-running-agent harness uses `claude-progress.txt` plus git commits. The community adds PreCompact archivers, Stop-hook tracers (Langfuse), CI artifact upload of `execution_file`, and retention guards (`cleanupPeriodDays: 3650`). No public tool gives completeness-disclosed renders out of the box, so you have to build that disclosure layer yourself (designs below).

## Key Findings

1. **The raw record exists and is complete.** The official `.claude` directory reference lists `projects/<project>/<session>.jsonl` as the "Full conversation transcript: every message, tool call, and tool result". It lists `projects/<project>/<session>/tool-results/` as the place for "Large tool outputs spilled to separate files".\[1\] The S2 losses (1,200/700-char cuts, missing `run_in_background`, missing mode events, missing "13. Create PR") were introduced by the render, not by Claude Code.
2. **The raw record has its own sharp edges that a parser must handle:**
   - Mid-turn user messages are not written as `type:"user"` lines. Community issue #86980 says such a message "is persisted only as an `attachment` record of type `queued_command`".\[2\]
   - Permission-mode changes are separate `permission-mode` records, plus a `permissionMode` key on user records.\[3\]
   - Compaction appends a `compact_boundary` record and a synthetic `isCompactSummary` user record, and earlier records stay in the file.\[4\]\[5\]\[6\]

   A parser that keeps only `type in {user, assistant}` reproduces exactly the S1/S2 blind spots.\[7\]
3. **Retention is the biggest silent threat.** `cleanupPeriodDays` defaults to 30 and has a minimum of 1.\[5\]\[8\] The docs say the sweep "deletes transcripts without showing a message".\[9\] GitHub issues document mass losses: in issue #85466, one sweep around 2026-08-06 "deleted roughly 950 transcripts covering 2026-04-15 → 2026-07-09 in one pass — including 917 transcripts of programmatic/agent runs", as a hard delete with no recycle bin.
4. **Truncation inside Claude Code is documented. Truncation inside renders is not.** Two cases need attention:
   - A failing Bash command gives the model only "a head-and-tail excerpt of that size cut from the read-back window, with no file path" once output exceeds roughly 10,000 characters (official Tools reference). The model's own evidence of a failure can therefore be partial, even though the JSONL records what the model saw.
   - Valid output over about 30,000 characters spills to a file under the session directory, and the transcript holds only a path plus a 2,000-character preview.\[10\] Evidence capture must therefore copy the `tool-results/` folder, not just the `.jsonl`.
5. **Cloud sessions and scratchpads are disposable by design:**
   - The scratchpad lives under the OS temp directory, and OS temp cleanup can wipe it.\[1\]\[11\]\[12\]
   - Cloud VMs pause and "can later be reclaimed", and there is no shell access and no documented raw-JSONL download.\[13\]
   - The only official way out is `claude --teleport`, which "loads the full conversation history into your terminal".\[14\]

   Anything not committed and pushed from a cloud VM should be treated as already lost.
6. **Compaction does not destroy the local record, but it does destroy the model's memory.** Locally the JSONL keeps everything before `compact_boundary`.\[4\]\[5\]\[15\] Anything the agent "knows" only from the conversation (the scratchpad-held H4 ledger, report v1) is gone from its context after compaction unless it was written to a file. Official PreCompact hooks can archive the record or block compaction.

## 4. Composite Practices (what actually works when no single tool does)

These are designs assembled from the verified mechanisms above. Hook semantics are verified; the scripts are **proposed patterns, not tested products**.

**P1 — Retention lock (E).** Set `"cleanupPeriodDays": 3650` in `~/.claude/settings.json`.\[68\] In CI, fail if `CLAUDE_CODE_SKIP_PROMPT_HISTORY` or a managed `cleanupPeriodDays` shorter than the audit window is in effect; the Agent SDK `resolveSettings()` reports provenance for this key.\[69\] Still back up `~/.claude/projects/` because the sweep is silent and irreversible.\[68\]

**P2 — Lossless capture hooks (E, C, S, F, T).** Register one script on `PreCompact`, `Stop`, `SubagentStop` and `SessionEnd`. It reads `transcript_path` from stdin and copies the `.jsonl` **plus** the sibling `<session-id>/` folder (`tool-results/`, `subagents/`) into a project-local `.evidence/<session-id>/<UTC-timestamp>-<event>/`. It never writes into the scratchpad. Keep SessionEnd work light (1.5 s budget) and make Stop the primary trigger. Optionally add a `PostToolUse` hook that appends `tool_name` + full `tool_input` JSON to `.evidence/<session>/tool-calls.ndjson`, an independent ledger of fields such as `run_in_background`.

```json
{
  "cleanupPeriodDays": 3650,
  "hooks": {
    "PreCompact":   [{ "hooks": [{ "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/capture-evidence.sh" }] }],
    "Stop":         [{ "hooks": [{ "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/capture-evidence.sh" }] }],
    "SubagentStop": [{ "hooks": [{ "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/capture-evidence.sh" }] }],
    "SessionEnd":   [{ "hooks": [{ "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/capture-evidence.sh", "timeout": 30 }] }],
    "PostToolUse":  [{ "matcher": "*", "hooks": [{ "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/log-tool-input.sh", "async": true }] }]
  }
}
```

**P3 — Manifest and hashing (U, S).** For each capture, the script writes `manifest.json` with these fields:
- `session_id`, `event`, `captured_at` (UTC), and the timestamp of the last JSONL record (the true snapshot cut-off);
- byte size, line count, and counts per record type (`user`, `assistant`, `system`, `permission-mode`, `queue-operation`, `attachment`, `compact_boundary`);
- the sha256 of every file, and the list of `tool-results/` files.

Hash-chain manifests (each includes the previous manifest's sha256) to make later edits detectable. This is the **completeness metadata that Claude Code does not provide (O16)**.

**P4 — Disclosed renders only (T, F, U).** Any human-readable render must start with a header that states:
- the source path and source sha256;
- the render tool and its version;
- per-field truncation limits, e.g. "tool_result truncated to 1,200 chars; 37 of 212 results cut; 418,331 chars omitted";
- the record types excluded, with counts.

Inline markers must read `[… N chars omitted — see <path>#L<line>]`. The output file name must say `render`/`excerpt`, never `full`. Enforce the name rule with a `PreToolUse` hook on `Write|Edit` that denies paths matching `*full*` under `.evidence/` unless a matching manifest says `complete: true`. Hook-based deny is a verified mechanism;\[23\] this specific rule is a proposed design.

**P5 — Auditor access contract (A, S).** Define an auditor subagent (`.claude/agents/evidence-auditor.md`, tools `Read, Grep, Glob, Bash(jq *)`) whose system prompt includes the following rules:
1. Evidence = raw JSONL + `tool-results/` at the given paths. Renders are indexes only.
2. Before any finding, verify the manifest sha256 and state the snapshot cut-off. Mark as "out of scope / not evidenced" any work after the last record timestamp.
3. Parse all record types, including `permission-mode`, `system`, `queue-operation` and `attachment.type=="queued_command"`. Quote `tool_use.input` verbatim (e.g. `run_in_background`).
4. Report every truncation encountered.

The orchestrator passes the paths and timestamps in the Task prompt and **re-runs capture (P2) immediately before spawning auditors**, so the snapshot covers the latest work. This prevents a repeat of the 21:43 freeze.

**P6 — Get evidence out of ephemeral environments (E).**
- In cloud sessions, ensure a single-repo session (repo hooks load). Have the Stop hook, gated on `$CLAUDE_CODE_REMOTE == "true"`, `git add .evidence/ && git commit && git push` to a dedicated evidence branch. The proxy allows pushes to branches but rejects tags and deletions.\[13\]
- Record `CLAUDE_CODE_REMOTE_SESSION_ID` and the claude.ai transcript URL in the manifest. Afterwards, `claude --teleport <id>` locally and re-capture the local JSONL.
- Rule in CLAUDE.md: "Reports, ledgers and fetched sessions are written to `docs/evidence/` and committed in the same turn; the scratchpad is for throwaway files only." This rule addresses report v1, the H4 ledger and the fetched session.

**P7 — Compaction strategy (C).** Use a PreCompact hook that archives (P2), and optionally exits 2 to block auto-compaction until capture succeeds. Pair it with a SessionStart `compact` matcher hook that re-injects pointers to `.evidence/` and the progress file. Keep agent working state in files (B1) so compaction cannot erase it.

**P8 — Independent second channel (E, A).** For high-stakes work, also enable OTel with `OTEL_LOG_TOOL_DETAILS=1`, `OTEL_LOG_USER_PROMPTS=1` and `OTEL_LOG_RAW_API_BODIES=file:<durable-dir>` (untruncated), or `tee` the stream-json output in headless runs. In CI, upload `execution_file` with `if: always()`.

## Recommendations

1. **Today:** set `cleanupPeriodDays: 3650` and back up `~/.claude/projects/`. Any surviving S1/S2 transcripts are recoverable only while the files exist.\[68\]
2. **Re-audit S1/S2 from raw JSONL, not from `my_session_full.txt`.**
   - Extract `tool_use.input.run_in_background`.
   - Extract the `permission-mode`/`system` records to settle S1's operating mode.
   - Extract the `queue-operation` + `attachment(queued_command)` records to recover "13. Create PR".
   - If S2 was a cloud session, teleport it first and capture immediately.
3. **Install P2 + P3 as project hooks** in `.claude/settings.json` so they also run in single-repo cloud sessions. Start from claude-compact-archive (C1) for PreCompact and extend it to Stop/SubagentStop/SessionEnd with manifests.
4. **Adopt P4 + P5 as policy:** no render without a disclosure header, no `*full*` names without a manifest, and auditors get raw paths, a manifest hash and a cut-off timestamp, refreshed right before they start.
5. **For cloud and CI work, adopt P6 + P8:** commit and push evidence every turn to an evidence branch; upload `execution_file`/stream-json with `if: always()`.
6. **Fix any parser or viewer you rely on** so it includes `queue-operation`/`queued_command` and `permission-mode` records. Prefer tools that report unknown record types instead of dropping them.

## Caveats

- **Schema is unofficial.** Record types such as `queue-operation`, `permission-mode` and `attachment.queued_command` come from community reverse-engineering and GitHub issues, not Anthropic documentation. They change between versions (several 2.1.2xx releases added new types). Re-verify against your installed version.
- **Version-specific numbers.** The thresholds (Bash ~30,000/~10,000 chars, 64 MiB, MCP 25,000 tokens/50,000 chars, OTel 60 KB) come from current docs as of October 2026 and have changed before (e.g. the Claude Code 2.1.51 changelog states "Tool results larger than 50K characters are now persisted to disk (previously 100K)").
- **Conflicting sources on PreCompact blocking.** The current official reference says exit 2 blocks compaction; older community docs say it cannot. Trust the current reference and test on your version.
- **Cloud unknowns.** These are not documented:
  - the in-VM JSONL path (likely `/root/.claude/projects/…`, an inference);
  - how long until a paused VM is reclaimed;
  - whether SessionEnd fires on pause or reclaim;
  - whether a teleported transcript is byte-identical to the server record.
- **Re-compaction duplication.** Issue #92089 reports that a second `/compact` in one process re-appends earlier history, so the transcript "grows quadratically".\[70\] Deduplicate by `uuid` when parsing and do not treat the duplication as tampering.
- **Privacy.** Lossless evidence contains secrets that tools read.\[63\] Committed or exported evidence branches need access control and, where appropriate, redaction that is itself disclosed in the manifest.

# R13: Enforcing Text Rules and Lessons in Every Claude Code Context

Writing a rule down in CLAUDE.md or a lessons file does not enforce it. The fix is three layers. First, turn every rule that can be checked into a hard gate in the action path: `permissions.deny`, PreToolUse hooks that exit 2, and Stop/SubagentStop gates. Second, inject the rules you can't check from a hook source that fires in every context: SessionStart with matcher `startup|resume|clear|compact`, plus SubagentStart. Third, pin agent parameters in agent definitions and environment variables instead of asking for them in prose. Anthropic's own docs say it plainly: CLAUDE.md is "context, not enforced configuration," and "To block an action regardless of what Claude decides, use a PreToolUse hook instead."\[1\]

## TL;DR
- **Enforce, don't describe.** Every rule a script can check belongs in `permissions.deny` or a PreToolUse/Stop/SubagentStop hook. Use exit 2 or a JSON `deny`/`block`, and set `onFailure: "block"` (v2.1.295+) so a broken hook doesn't fail open. Only the leftover judgment rules stay as text, and they get injected rather than left in a file someone has to open.
- **Copy the Superpowers pattern for owner rules.** Superpowers survives compaction verbatim because its SessionStart hook fires on `startup|clear|compact` and prints its text again each time. Its maintainer rejected narrowing the matcher because that "breaks superpowers after every compaction or clear". Register your own owner-rules hook the same way, and add a SubagentStart hook, because SessionStart context doesn't reach subagents. Put it at user or managed scope so every project and helper gets it.
- **Some gaps have no clean fix.** No hook can change a subagent's system prompt (feature request #23885), and rewriting a spawn's model through PreToolUse `updatedInput` has been reported as ignored (#39814). Read deny rules are "best-effort" and leak through `grep -r .`, `find` and script one-liners. Hiding `MyBest/` completely needs a Read deny, the OS sandbox and an output-filter hook together, or a container that doesn't mount the folder.

## Key Findings

1. **Anthropic says text rules are advisory.** The memory docs say CLAUDE.md "is delivered as a user message after the system prompt… there's no guarantee of strict compliance." They also say "if two instructions contradict each other, Claude may pick one arbitrarily." The documented remedy is to write anything that "must run at a specific point" as a hook.\[1\] Your observation that every broken rule existed only as text is the documented failure mode, not bad luck.
2. **What survives compaction depends on how it was loaded, not on how important it is.** The context-window docs list what is re-injected after compaction: project-root CLAUDE.md, unscoped `.claude/rules/`, auto memory, and the output of SessionStart hooks matching `compact`. Path-scoped rules and nested CLAUDE.md files are summarized away. Claude Code also "re-reads up to five of the files Claude has read or edited in the session, choosing the ones modified most recently".\[2\] That is exactly the "survives by chance" behaviour you saw for owner imperatives.
3. **Superpowers wins attention by construction, not by quality.** Its hook injects the whole `using-superpowers` SKILL.md wrapped in `<EXTREMELY_IMPORTANT>` (issue #2487).\[3\] One user measured 521 fires and 1.74 MB of byte-identical text across startup, clear and compact. When a PR tried to drop `clear|compact`, obra replied it "breaks superpowers after every compaction or clear" (PR #2279, Sep 2026).\[4\] Owner rules lose that contest because they sit in files that have to be read by hand.
4. **SessionStart context does not reach subagents, so SubagentStart is the official bridge.** SubagentStart can't block, but it returns `hookSpecificOutput.additionalContext` into the subagent's own context.\[5\]\[6\] Hooks from settings files, managed policy and plugins all fire inside subagents, and the hook input carries `agent_id`/`agent_type`.\[6\] Three things do not carry over: the main session's auto memory, output styles, and the Claude Code system prompt itself, because a subagent receives "only this system prompt plus basic environment details." The built-in Explore and Plan agents also skip CLAUDE.md.\[1\]\[7\]
5. **Agent parameters can be pinned without prose.** Frontmatter supports `model`, `effort`, `tools`, `disallowedTools`, `permissionMode`, `hooks`, `skills`, `maxTurns` and `omitClaudeMd`. `CLAUDE_CODE_SUBAGENT_MODEL` combined with `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` (v2.1.257+) forces one model on every subagent. `CLAUDE_CODE_EFFORT_LEVEL` overrides both the frontmatter `effort` and the per-call effort. Thinking is inherited from the session, and there is "no per-subagent thinking setting."\[7\]
6. **No mechanism fully hides a folder.** Read deny rules filter Read, Grep and Glob, and since v2.1.257 they also cover recognized Bash readers.\[8\] The docs say they "don't apply to a command that reads files without naming them, such as `grep -r pattern .`… or… a Python or Node script." `.claudeignore` "has no effect," and `respectGitignore` only controls the `@` file picker.\[8\]\[9\]\[10\] Since the Glob/Grep tools are off by default on macOS/Linux, `find`, `grep` and `ls` run through Bash, which makes Bash the main leak.\[11\]
7. **Some lesson-to-rule tooling already exists.** Anthropic's own **hookify** plugin turns corrections into enforced hook rules: `/hookify` with no arguments analyzes the conversation and generates `.claude/hookify.*.local.md` rules.\[12\]\[13\] Community tools cover the text side: claude-reflect queues corrections for CLAUDE.md, and claude-lessons graduates them via a Stop hook.\[14\]\[15\] Only the hookify-style path closes the loop into enforcement. The others still produce text.

**No official mechanism exists for:** (1) editing or prepending a subagent's *system prompt* from a hook (FR #23885); (2) changing a spawn's model from a hook. `updatedInput` on the Agent tool was reported ignored in v2.1.85+ (#39814), and SubagentStart has no `updatedInput` (FR #69545).\[23\]\[36\] (3) A per-subagent thinking setting. (4) Delivering owner text to subagents through output styles. (5) Hiding a directory from every listing (`.claudeignore` "has no effect"; FRs #29455, #30810). (6) Turning a lesson into a rule automatically. Anthropic ships this only as a plugin (hookify), not as a core feature.

**Conflict to flag:** FR #69545 says PreToolUse with matcher `Agent` "does not fire."\[23\] The current hooks reference documents a PreToolUse `Agent` input schema with `model` and `subagent_type`, plus a `resolvedModel` field (v2.1.212+),\[6\] and several community repos block Agent spawns from PreToolUse successfully.\[6\] Treat *blocking* an Agent call as working and *rewriting* it as unreliable, and test on your version.

### 4. Mapping to your specific failures

- **"The oath sits in a file no session loads."** Move it into a file loaded from disk (`~/.claude/CLAUDE.md` or `@~/.claude/oath.md`) **and** print it from SessionStart(`startup|resume|clear|compact`) and SubagentStart. Rewrite it as checkable facts; the docs warn that imperative "system command" text can trip prompt-injection defenses.\[6\]
- **"Owner imperatives don't reach helpers."** Use a SubagentStart hook with no matcher, and put the rules in every custom agent's body. For `-p` runs, add `--append-subagent-system-prompt-file`. Don't rely on auto memory or output styles; neither reaches subagents.\[1\]\[30\]\[62\]
- **"S2 doesn't apply S1's rules (model, effort, background helpers)."** Pin `model`/`effort` in agent frontmatter. Set `CLAUDE_CODE_SUBAGENT_MODEL(_FORCE)` and `CLAUDE_CODE_EFFORT_LEVEL` in the `env` block of user or managed settings. Gate `Agent` with a PreToolUse deny for missing or wrong `model`/`subagent_type`. "Must use helpers" can only be gated softly, for example with a Stop hook that blocks if the transcript shows no Agent call for task types that require one.
- **"Remedies phrased as habits."** Habits can't be executed. Turn each one into a hookify rule, a test, or a Stop/agent-hook check, and refuse any lesson that doesn't name its enforcing artifact.
- **"Superpowers wins attention."** Give owner rules the same delivery channel, or narrow Superpowers. You can't edit a plugin's hooks.json safely, but you can disable the plugin per project, or use `allowManagedHooksOnly` to block non-managed plugin hooks. That breaks Superpowers' bootstrap after compaction, which is the trade-off obra pointed out.\[4\]
- **"`MyBest/` still shows up in listings."** See the folder recipe below.

### 5. Folder exclusion (g)

| Layer | What it covers | Gap |
|---|---|---|
| `permissions.deny: ["Read(MyBest/**)"]` | Read, Grep/Glob results (filtered since the v2.1.162 fix), `@` mentions, recognized Bash readers (`cat`, `head`, `tail`, `sed`, `tac`, `egrep`, `< file`; v2.1.257+), nested `MyBest/` at any depth | "Best-effort."\[8\] Doesn't cover `grep -r .` from a parent, `find`, python/node scripts, or `@imports`. #28008 (Glob/grep -r leak) was closed "not planned"; #91995: a `./`-prefixed rule triggers ancestor-match prompts on `grep -r .`; v2.1.259 widening partly reverted in 2.1.260; symlink bypass CVE-2026-25724 fixed in 2.1.7\[8\]\[63\]\[64\]\[65\]\[66\]\[67\] |
| `sandbox.enabled` + `filesystem.denyRead: ["./MyBest"]` + `allowUnsandboxedCommands: false` + `failIfUnavailable: true` | OS-level reads by all Bash child processes, including python/node\[68\]\[69\] | Doesn't apply to Claude's file tools,\[33\] hooks, MCP servers or `!` commands; may not hide the *name* in `ls` of the parent; no native Windows\[32\] |
| PreToolUse hook on `Bash\|Glob\|Grep\|Read` | Denies any input string containing `MyBest` | String matching is evadable (globs, variables) |
| PostToolUse `updatedToolOutput` on Bash/Glob | Strips `MyBest` lines from what Claude sees | Output must match the tool's schema exactly, or it is silently ignored; telemetry still sees the original\[6\] |
| Container/VM without the folder mounted | Everything | Highest setup cost; the only complete boundary |

`respectGitignore` affects only the `@` picker, Glob ignores `.gitignore` by default (`CLAUDE_CODE_GLOB_NO_IGNORE=false` flips it, with side effects; #97866), and `.claudeignore` does nothing.\[9\]\[10\]\[11\]\[70\]

## Recommendations: ranked architecture for R13

1. **Hard gates first (sub-problems a, f, g).** Put `permissions.deny` for forbidden paths, commands and agent types in user settings, or in managed settings at `/etc/claude-code/managed-settings.json` so no project can weaken them. Add PreToolUse hooks with exit 2 and `onFailure: "block"` for every checkable rule, including a guard on `Agent` that denies spawns missing the required `model` or `subagent_type`. Add Stop/SubagentStop gates that run tests and lesson-checks, with a `stop_hook_active` guard. This is the only layer that works even when the rules aren't in the model's attention.
2. **Pin agent parameters in configuration (f).** Every custom agent in `~/.claude/agents/` gets explicit `model`, `effort`, `tools`/`disallowedTools` and `permissionMode`, with owner rules in its body. Set `CLAUDE_CODE_EFFORT_LEVEL`. Use `CLAUDE_CODE_SUBAGENT_MODEL(_FORCE)` only if one model for all agents is acceptable. Don't ship enforcement-critical agents as *plugin* agents, because plugin agents ignore the `hooks` and `permissionMode` fields.\[7\]
3. **Inject what can't be gated into every context (b, c), Superpowers-style.** A user/managed SessionStart hook with matcher `startup|resume|clear|compact|fork` prints a ≤10K-char `owner-rules.md` written as facts. A SubagentStart hook (no matcher) emits the same file via `hookSpecificOutput.additionalContext`. For `-p`/CI runs, add `--append-system-prompt-file` and `--append-subagent-system-prompt-file`. Keep a one-line pointer in root `~/.claude/CLAUDE.md` as a backstop that reloads from disk.
4. **Close the lesson loop (d).** Every retrospective entry must produce an artifact: a hookify rule, a test, a deny rule or a Stop check. Use hookify (bare `/hookify`) after any session where you corrected Claude. Use claude-reflect only for non-checkable preferences. Optionally, add an agent-type Stop hook that rejects "lessons" phrased as habits ("read more carefully") with no enforcing artifact.
5. **Keep text small and consistent (e).** Root CLAUDE.md under 200 lines, as a soft target: CLAUDE.md loads in full, only MEMORY.md is capped at 200 lines/25KB, and the docs say shorter files "produce better adherence." Run `/doctor prompt-audit` regularly. Use one source file for owner rules, imported or injected, never copied. Watch drift with an `InstructionsLoaded` audit log. Decide explicitly whether Superpowers stays on, since its `<EXTREMELY_IMPORTANT>` text will otherwise outrank owner rules.
6. **Folder exclusion (g).** Read deny + sandbox denyRead (strict) + PreToolUse string guard + PostToolUse output filter. Use a container if the boundary has to be absolute.
7. **Verify with canaries.** Put a unique codeword in owner-rules and ask the main session, a fresh subagent, and a post-`/compact` session to repeat it. Known injection bugs (#15174, #16538, #88086, #93458) fail silently.\[17\]\[18\]\[19\]\[20\]

## Caveats and remaining gaps
- **No hook can rewrite a subagent's system prompt or model.** Injection lands in user context, which the subagent can itself compact.\[22\] Prompt-level guarantees for subagents exist only through agent-file bodies and `--append-subagent-system-prompt` in `-p` mode.
- **Judgment rules ("think before acting," "use background helpers when appropriate") can't be verified deterministically.** Prompt or agent hooks only add a second model's judgment.
- **Read deny is "best-effort,"** and Bash coverage has changed across 2.1.257–2.1.260.\[64\]\[71\] Retest after every upgrade.\[8\]\[64\]
- **Version dependence.** Many fields cited here appeared in 2.1.198–2.1.295 (Oct 2026).\[72\] Older installs lack `onFailure`, `MODEL_FORCE`, per-call effort and `prompt-audit`.
- **Partly unverified.** SubagentStart re-injection after subagent auto-compaction comes from a secondary source; the 8-continuation Stop cap is confirmed in the hooks reference. Star and install counts are platform-reported. The emphasis-keyword effect is Anthropic's anecdote: Alex Dunlop notes "No study has tested it," and the arXiv preprint he cites (2605.10039, 1,650 sessions) found no measurable effect from file length, rule position or layout.

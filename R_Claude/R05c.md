# R05: Ways to stop Claude Code treating subagent output as fact and writing biased briefs

**Bottom line:** Claude Code has no built-in way to mark a subagent's output as verified or unverified. The fix you can actually enforce is to treat every hand-back as an unverified claim and gate it in four places: (1) a `PreToolUse` hook on the `Agent` tool that rejects briefs missing required clauses; (2) a `SubagentStop` hook (command, prompt or agent type) that rejects outputs with no file:line evidence; (3) a separate refuting verifier, either a fresh subagent or a dynamic-workflow verify stage, that re-checks claims against primary sources; and (4) a `Stop` hook or coverage-manifest gate that blocks the orchestrator from finalising until every helper file has been read and every artifact has a reviewer. Everything else (brief templates, "nothing found is allowed", blind reviewers, accuracy ledgers) can be enforced only partly, through subagent definitions, skills and hooks. Asking clarifying questions back is not officially supported at all.

## TL;DR

- **Verification of hand-backs (a, b, e).** Anthropic's own guidance is to separate the doer from the grader. Its docs say: "Have Claude show evidence rather than asserting success". A verification subagent "has a fresh model try to refute the result, so the agent doing the work isn't the one grading it". The Research system adds a dedicated CitationAgent and filesystem artifacts so the lead doesn't play a "game of telephone". To make this hard rather than advisory, add `SubagentStop` hooks (which receive `last_assistant_message` and `agent_transcript_path`) and a read-before-edit gate.
- **Brief quality (c, g).** Anthropic says each subagent needs "an objective, an output format, guidance on the tools and sources to use, and clear task boundaries", plus effort-scaling rules. You can hard-enforce this with a `PreToolUse` hook matched on `Agent` that denies non-compliant `tool_input.prompt` values. Issue #39814 (filed against Claude Code "2.1.85+") reports that `permissionDecision` is "respected (allow/deny works)" but `updatedInput` is "silently dropped; subagent receives original prompt verbatim". Its fix status is unconfirmed. Fixed clauses belong in `.claude/agents/*.md` system prompts or in `SubagentStart` `additionalContext`, not in ad-hoc text.
- **Coverage, ledgers, clarification (d, e, f).** There is no official mechanism for coverage manifests or helper-accuracy ledgers. Build them yourself from hooks plus files. Subagents cannot call `AskUserQuestion`, because the docs remove it from every subagent.\[1\] The workarounds are a mandatory "QUESTIONS/ASSUMPTIONS" output section plus `SendMessage` resume, and resume is token-expensive.

#### 1.2 Claude Code primitives that apply to R05 (verified against current docs)

**Subagent definition fields** (`.claude/agents/*.md`, `~/.claude/agents/`, managed settings, `--agents` JSON; https://code.claude.com/docs/en/sub-agents):
- `tools` / `disallowedTools`.\[1\] A read-only verifier uses `tools: Read, Grep, Glob`, which stops the verifier from "fixing" what it was meant to judge.\[1\]
- `effort` (`low|medium|high|xhigh|max`). Per-invocation `effort` is also allowed (v2.1.292+).\[1\] This addresses "lacked effort" in (c).
- `maxTurns`. On hitting the limit, "Claude Code returns its output marked as partial" (v2.1.246+).\[1\] Truncation becomes visible instead of being passed off as complete.
- `skills`. Preloads full skill content,\[1\] so a brief template or checklist can be injected deterministically.\[1\]
- `hooks`. Scoped to the subagent. A frontmatter `Stop` hook is converted to `SubagentStop`.\[1\]\[14\]
- `memory` (`user|project|local`) gives persistent per-agent memory.\[1\] It can hold a helper's own error log (e).
- `omitClaudeMd: true` (v2.1.271+), "for subagents that take everything they need from the delegation prompt".\[1\] This lets you strip shared framing for blind reviewers (c).
- `model`. Use a different model or family for reviewer diversity.
- `isolation: worktree`.\[1\]
- Built-in **Explore** takes a thoroughness level: "quick… medium… very thorough".\[1\]

**What a subagent sees.** From the "What loads at startup" section, quoted by the subagent: "Each subagent starts with a fresh, isolated context window. It doesn't see your conversation history, the skills you've already invoked, or the files Claude has already read. Claude composes a delegation message that summarizes the task." Initial context is the system prompt, the task message ("the delegation prompt Claude writes"), CLAUDE.md files (except Explore/Plan or `omitClaudeMd`), a git status snapshot, preloaded skills, and a sibling roster. Official advice: "If a rule must [reach the subagent]… restate it in the prompt you give Claude when delegating." Also: "The @-mention controls which subagent Claude invokes, not what prompt it receives."\[1\] This confirms the R05 mechanism, "agents see only their brief", as documented behaviour.

**Tools removed from every subagent:** `AskUserQuestion`, `EnterPlanMode`, `Agent` at the depth limit, and others.\[1\] Subagents structurally cannot ask the user (f). Follow-ups go through `SendMessage` to the agent ID, which "resumes in the background".\[1\]

**Restricting delegation:**
- `permissions.deny` with `Agent(name)` blocks specific subagent types.\[1\]
- Denying `Agent` blocks all delegation.\[1\]
- `tools: Agent(worker, researcher)` is an allowlist, but only for a main-thread agent run via `claude --agent`.\[1\]

**Headless brief injection:** `--append-subagent-system-prompt` / `--append-subagent-system-prompt-file` (v2.1.205 / v2.1.261+) appends fixed text to every subagent's system prompt.\[1\] This is the closest official "mandatory clause" mechanism, and it works only in `-p` mode.

**Hooks** (https://code.claude.com/docs/en/hooks):

**Dynamic workflows** (research preview, v2.1.154+; https://claude.com/blog/introducing-dynamic-workflows-in-claude-code): "Agents address the problem from independent angles, other agents try to refute what they found, and the run keeps iterating until the answers converge". Bug hunts "run independent verification on every finding".\[19\] This is the only native structure where verification of each finding is part of the orchestration script rather than the model's discretion. Community observation, not documented: the bundled `/deep-research` sends each claim to 3 skeptic agents and keeps it only if fewer than 2 refute it (https://gist.github.com/Drizzt321/234f03be4749a8b4c012791a8a04cdfc). \[20\]

**Agent SDK:**
- `outputFormat` / `output_format: {type: "json_schema", schema}` returns validated `structured_output`.\[21\] Use it to force per-claim fields such as `claim`, `evidence_path`, `line`, `quote`, `status`. Source: https://code.claude.com/docs/en/agent-sdk/structured-outputs.
- `AgentDefinition` (subagents) does not accept `output_format` (https://github.com/anthropics/claude-agent-sdk-python/issues/440). \[22\] Schema enforcement therefore applies at the top-level `query()`, not per subagent.
- SDK hooks include `SubagentStop` with `agent_transcript_path`.\[23\]

### 2. How the big players handle it

- **Anthropic Research system.** The lead plans in extended thinking, defining "each subagent's role".\[3\] Briefs carry objective, format, tools/sources, boundaries and effort.\[2\] Subagents write artifacts to storage and pass references.\[5\] A separate CitationAgent attributes claims.\[4\] An LLM judge checks "do claims match sources?" Human testers catch bias, for example a preference for SEO content farms.\[3\] The takeaway for R05: the lead never cites from summaries, and attribution is a separate pass with access to the documents.
- **Anthropic harness (planner/generator/evaluator).** The evaluator is a separate agent, tuned to be skeptical, with concrete grading criteria and real tools (Playwright).\[24\]\[25\] Its prompt is iterated by reading its own logs for divergences from human judgment.\[8\] That is effectively a helper-error ledger feeding brief revision (e, g).
- **Anthropic Claude Code product.** The bundled `/code-review` skill reviews the diff "in a fresh subagent".\[11\] Dynamic workflows make refute-each-finding the default for audits.
- **Cognition (Devin), "Don't Build Multi-Agents"**, https://cognition.com/blog/dont-build-multi-agents. Principle 1: "Share context, and share full agent traces, not just individual messages".\[26\] Principle 2: actions carry implicit decisions, and conflicting decisions produce bad results.\[27\] Relevance to R05: a brief that is an author-written summary is exactly the lossy channel they warn against. Their remedy is passing raw traces/paths rather than paraphrase (c, f).
- **OpenAI.** The Responses API multi-agent guide (https://developers.openai.com/api/docs/guides/responses-multi-agent) makes the root agent "responsible for synthesizing subagent responses", with spawn/message/wait primitives.\[28\] Codex defaults reported secondhand (firecrawl.dev): `agents.max_threads` 6 and `agents.max_depth` 1, with the advice to "cap the fan-out at what you can actually verify".\[29\] I found no OpenAI-specific mechanism for verifying delegate claims. Treat this as context only.
- **Industry practitioners.** Addy Osmani (https://addyosmani.com/blog/code-agent-orchestra/): "Never trust agent output without verification". His three gates are plan approval, hooks, and AGENTS.md learning.\[30\] I found no sourced Cursor or Sourcegraph material specific to orchestrator verification of delegate output, so they are omitted.

### 4. Implementable recipes (composed from documented primitives; **inferred**: I found no single ready-made artifact doing exactly this)

**4.1 Brief linter: PreToolUse on `Agent` (c, g). Hard deny.**
```json
{"hooks":{"PreToolUse":[{"matcher":"Agent","hooks":[{"type":"command","command":"python3","args":["${CLAUDE_PROJECT_DIR}/.claude/hooks/brief_lint.py"],"onFailure":"block"}]}]}}
```
```python
# brief_lint.py: deny briefs missing mandatory clauses or containing framing
import json,sys,re
d=json.load(sys.stdin); p=d["tool_input"].get("prompt","")
req={"OBJECTIVE:":"objective","SCOPE/ARTIFACTS:":"artifact list","RAW PATHS:":"raw source paths",
     "EFFORT:":"effort/tool-call budget","EVIDENCE RULE:":"file:line+quote rule",
     "NOTHING FOUND IS AN ACCEPTABLE RESULT":"null-result clause","OUTPUT FILE:":"raw output path",
     "QUESTIONS/ASSUMPTIONS:":"ambiguity section"}
missing=[v for k,v in req.items() if k not in p]
framing=re.findall(r"(the only (allowed )?difference|confirm that|verify that .* is correct|\b\d{3,4}[- ]words?\b|max(imum)? \d+ words)",p,re.I)
if missing or framing:
    print(json.dumps({"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny",
      "permissionDecisionReason":f"Brief rejected. Missing: {missing}. Framing/caps found: {framing}. Rebuild from /brief template; quote sources, don't paraphrase from memory."}}))
```
Limitation: rewriting the brief via `updatedInput` is unreliable for `Agent` (#39814).\[50\] Deny-and-retry is the dependable path. Regex framing detection is heuristic.

**4.2 Fixed clauses injected regardless of what the author writes: SubagentStart (c, g).** Matcher on agent type (for example `^reviewer$`), returning `hookSpecificOutput.additionalContext` with the evidence rule, "nothing found is allowed", "you were not told the expected answer; do not infer one", and "list questions/assumptions". Equivalent alternatives are a subagent system prompt or the `skills:` preload of a `brief-contract` skill. Headless: `--append-subagent-system-prompt-file`.

**4.3 Evidence gate on hand-back: SubagentStop (b).** A command hook parses `last_assistant_message` and blocks unless every finding line matches `path:line` plus a `Quote:` or explicit `NOTHING FOUND`, and the declared `OUTPUT FILE` exists. Guard with `stop_hook_active` to avoid loops. A stronger variant uses `type: "agent"` (experimental), prompted to Read each cited `path:line` and confirm the quote is present. That is a native spot-checker.

**4.4 Read-before-act gate (a).** `PostToolUse` on `Agent` appends each subagent's OUTPUT FILE to `.claude/state/helper_outputs.json`. `PostToolUse` on `Read` appends opened paths. `PreToolUse` on `Edit|Write`, with `if: "Edit(reports/**)"`, denies edits to the report while any helper output is unread. This directly blocks "report v4 edited from hand-back summaries before the helper files were opened."

**4.5 Coverage manifest (d).** A `coverage.json` lists every in-scope artifact (plan, rules/oath, report, current turn…) mapped to an assigned reviewer and output file. A `Stop` hook blocks finishing while any artifact has no reviewer output. A `PreToolUse` `Agent` hook can require briefs to name a manifest artifact ID.

**4.6 Independent reviewers, for real (c).**
- Separate agent definitions with different system prompts, models or `effort`.
- `omitClaudeMd: true` so shared CLAUDE.md framing doesn't leak in.
- Briefs that state the question but not the author's hypothesis. The pedrohcgs rule is "Do NOT include the draft text".\[33\]
- A named non-fork subagent rather than a fork, since forks inherit the parent conversation.\[1\]

**4.7 Volume (a).** Do not batch-accept 174 remarks. Route them through a refute stage: a dynamic workflow `audit-and-verify`, or one verifier per claim cluster. Accept only survivors, with each acceptance carrying evidence.

**4.8 Helper-error ledger (e).** When the orchestrator or a verifier rejects a helper claim, append `{agent_type, brief_id, claim, verdict, evidence}` to `.claude/state/helper_ledger.jsonl`, either from the verifier's output or from a SubagentStop hook on the verifier type. SubagentStart can inject that agent type's past error summary. Periodically feed the ledger to Claude to revise agent prompts, mirroring Anthropic's evaluator-log tuning loop.

**4.9 Clarification channel (f).** The brief requires a `QUESTIONS/ASSUMPTIONS:` section. The subagent states its assumptions explicitly and may stop early with questions. The orchestrator answers via `SendMessage` to the agent ID. Cost caveat: resume replays the full transcript (https://github.com/anthropics/claude-code/issues/87106). \[51\] Handback-after-resume bugs are open (#96849, #98241).\[52\]\[53\] For cheap questions, prefer a fresh subagent with a corrected brief.

## Caveats

- **Version sensitivity.** Several fields cited here are recent and versioned: `omitClaudeMd` v2.1.271, per-invocation `effort` v2.1.292, `onFailure` v2.1.295, `maxTurns` partial marking v2.1.246, `SubagentHandback` v2.1.271.\[1\]\[14\] Check `claude --version` before relying on them.
- **Unconfirmed points.**
  - Whether issue #39814 is fixed. Status was not visible.
  - The "3 skeptics, <2 refute" `/deep-research` rule. This is a community observation, not documented.
  - The "early victory problem" wording, which I saw only in a secondary summary.
  - ariff plugin claims, which are unvetted.
- **Inferred, not sourced as existing artifacts.** Recipes 4.1–4.9 are my compositions of documented hook and agent primitives. Test each gate. orchestkit #4158 shows gates that silently never fire.
- **Limit of verifiers.** LLM verifiers share failure modes with the helpers they check, and Anthropic notes Claude is "a poor QA agent" out of the box.\[8\] Hard gates guarantee that evidence and steps exist, not that the evidence is correct. Mechanical checks (grep of the quoted text at `path:line`) are the only truly deterministic layer.

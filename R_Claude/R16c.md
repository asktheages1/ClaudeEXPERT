# R16 — Making Claude Code Surface Knowledge-Base Gaps and Overgeneralisations: Mechanisms, Practices and Ready-Made Solutions (state as of 11 Oct 2026)

No single Claude Code feature solves R16, but you can largely close it by combining four things: a provenance schema in `knowledge/` that tags every claim as sourced, observed or inferred; deterministic hooks (PostToolUse lint, a Stop gate, a SessionStart version check) that refuse untagged, unmirrored or stale claims; a separate verifier subagent that checks scope, similar to Anthropic's own CitationAgent; and a gap ledger that a Stop hook will not let Claude close until each gap has gone to the owner through `AskUserQuestion`. Instructions in CLAUDE.md alone are the reason R16 happened. The A4 audit found the rule "offer the owner a choice" was written down but not followed, so that rule needs a hook behind it.

## TL;DR

- **Officially available building blocks:** Anthropic has documented primitives for each sub-aspect, but not a finished solution. The primitives are Stop/SubagentStop `decision: "block"`, prompt and agent hooks, PostToolUse feedback, SessionStart `additionalContext`, `InstructionsLoaded`, the `AskUserQuestion` tool (which hooks can match), subagents with restricted tools, and the guidance to "allow Claude to say I don't know", ground in direct quotes and retract claims that have no quote. There is **no official mechanism** for provenance tagging, local doc mirroring, staleness detection of a knowledge base, or "offer the owner a choice" enforcement. Those have to be built from hooks.
- **What the big players do:** Anthropic keeps writing and verification apart. Its Research system runs a separate CitationAgent over the sources and the report, and its evals score "factual accuracy" and "citation accuracy" separately. It keeps state in external files (claude-progress.txt, a JSON feature list it chose because models are less likely to overwrite JSON) and tells users to give Claude a pass/fail check and to have Claude "interview" them with `AskUserQuestion`. GitHub's Spec Kit makes uncertainty explicit with `[NEEDS CLARIFICATION]` markers and blocks on a checklist item "No [NEEDS CLARIFICATION] markers remain".\[1\]
- **Recommended stack for this project:** (1) frontmatter provenance and a `claim_type` tag on every `knowledge/` entry; (2) a PostToolUse lint hook on writes to `knowledge/**` and output docs that rejects untagged claims, citations with no local mirror, and quotes that do not appear verbatim in the mirror; (3) a scope-checker agent hook or subagent for overgeneralisation; (4) a `gaps.md` ledger plus a Stop hook that blocks until every gap has been presented through `AskUserQuestion`, with a PostToolUse hook on `AskUserQuestion` recording the owner's choice; (5) a SessionStart hook that compares `claude --version` and the in-session tool list with the version stamps on every "Claude Code self-knowledge" claim.

## Key Findings

1. **Why R16 happened.** O0 mixed sourced facts with inferences ("waiting = inactivity" stretched beyond a source that names only MCP approvals). Decisions relied on facts that were never recorded (the 120-second threshold, `CLAUDE_AUTO_BACKGROUND_TASKS`, the container Stop hook and its `jq` dependency, the colon in a skill name, cloud vs local differences). Cited GitHub docs were not mirrored. Gaps were noted but never offered to the owner as a choice. A claim about Claude Code's own Agent tool (no `effort` field) was stale. Anthropic's own issue tracker documents both failure modes: issue #98235 reports "Claude presented its own inference as a sourced fact, and the source said the opposite", noting "No provenance labels. Sourced facts, Claude's inferences, and press speculation all appeared in the same confident voice".\[2\] Issue #27430 describes MEMORY.md acting as a "confabulation amplifier" ("Session N: Claude guesses → writes guess to MEMORY.md; Session N+1: Claude reads MEMORY.md → treats guess as verified fact").\[3\]
2. **The stale claim in O0:62 is a textbook case of version drift.** The current official subagents page lists `effort` as a frontmatter field ("Effort level when this subagent is active. Overrides the session effort level…")\[4\] and says a per-invocation effort parameter "overrides the effort field and stays in effect when the subagent is resumed. The per-invocation parameter requires Claude Code v2.1.292 or later."\[4\] An earlier comment in GitHub issue #43083 had said "There isn't a per-call effort parameter on the Agent tool itself".\[5\] That was true at the time and false after v2.1.292. A claim about Claude Code's tooling without a version stamp goes stale this way.
3. **Several facts missing from `knowledge/` are in official docs that were simply never mirrored.** The hooks reference states that its Bash examples use `jq` ("install `jq` and make sure it is on your `PATH`"). It also says `$CLAUDE_CODE_REMOTE` is `"true"` in remote web environments and unset locally; the official env-vars page adds that it is "Set automatically to true when Claude Code is running as a cloud session. Read this from a hook or setup script to detect whether you are in a cloud session." The hooks reference also says cloud sessions "don't read your local `~/.claude/settings.json`", and that Claude Code checks "a Bash command's auto-background eligibility against the input your hook returns".\[6\] The subagents page says names "can't contain `:`, which is reserved for plugin-scoped identifiers".\[4\] These cover the `jq` dependency, the colon issue and part of "why cloud and local differ". For skills, the Claude Platform "Skill authoring best practices" page limits `name` to "Maximum 64 characters, lowercase letters/numbers/hyphens only, no XML tags, no reserved words" ("anthropic", "claude"), which rules out a colon. I could not confirm that the code.claude.com skills page applies the same rule, so record it as sourced from the Platform page only.
4. **Hooks are the only hard-enforcement layer, and they have limits.** Stop/SubagentStop can block with a reason. Prompt hooks (single-turn model judgement) and agent hooks (a subagent with Read/Grep/Glob; "experimental and may change") can judge things like scope. `onFailure: "block"` (v2.1.295+) makes a crashing policy hook fail closed, but has no effect on Stop/SubagentStop.\[6\] The official env-vars page documents the loop cap: `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` is the "Maximum number of consecutive times a Stop or SubagentStop hook may block the turn from ending before Claude Code overrides it and ends the turn anyway (default: 8). Set to 0 to disable the cap." The hooks reference adds that "The count of consecutive continuations resets each time Claude calls a tool." The claim that the cap arrived in v2.1.143 comes only from third-party guides.
5. **`AskUserQuestion` can be matched by hooks, but it has a bug history.** The hooks reference now lists `AskUserQuestion` among the tools PreToolUse matches and documents `permissionDecision: "defer"` for headless runs.\[6\] Earlier issues reported that catch-all PreToolUse hooks broke or emptied `AskUserQuestion` results (#13439, #12031), a `defer` race (#64389, cited by gstack #2292), and a third-party hook denying every `AskUserQuestion` call (CodeIsland #340, on Claude Code 2.1.261).\[7\]\[8\]\[9\]\[10\] Use narrow matchers and test with your version.

## Details

### 1. Official recommendations and mechanisms

#### 1.1 Prompting guidance for grounding (soft)

Anthropic's "Reduce hallucinations" guide (platform docs) gives three basic strategies that map directly to sub-aspect (a):
- "Allow Claude to say 'I don't know': Explicitly give Claude permission to admit uncertainty. This simple technique can drastically reduce false information."\[11\]
- "Use direct quotes for factual grounding … ask Claude to extract word-for-word quotes first before performing its task."\[12\]
- "Verify with citations: Make Claude's response auditable by having it cite quotes and sources for each of its claims. You can also have Claude verify each claim by finding a supporting quote after it generates a response. If it can't find a quote, it must retract the claim."\[12\]
- The same page also lists "External knowledge restriction: Explicitly instruct Claude to only use information from provided documents and not its general knowledge", plus chain-of-thought verification and best-of-N comparison.\[13\]

The **"retract if no quote"** rule is the most direct official countermeasure to overgeneralisation. It would have caught "waiting = inactivity", because no quote in H2_links.md supports anything beyond MCP approvals. The Citations API (Jan 2025) is the API-level version: Claude "automatically cites claims in its output that are inferred from those sources". In Anthropic's launch post "Introducing Citations on the Anthropic API", Thomson Reuters (CoCounsel) reported: "we reduced source hallucinations and formatting issues from 10% to 0% and saw a 20% increase in references per response." The same post says "Claude's built-in citation capabilities outperform most custom implementations, increasing recall accuracy by up to 15%." *Note:* Citations is an API feature. Claude Code has no built-in citation mode, so in Claude Code you get this pattern through instructions and hooks. **No official mechanism** exists for Citations inside Claude Code sessions.

#### 1.2 Claude Code best practices (soft, but explicitly pointing to hard gates)

The current best-practices page (code.claude.com/docs/en/best-practices, undated living doc; references v2.1.283+, `/goal`, `/verify`) says:
- "Give Claude a check it can run… Claude stops when the work looks done. Without a check it can run, 'looks done' is the only signal available, and you become the verification loop."\[14\]
- "Have Claude show evidence rather than asserting success." It lists four ways to gate: in one prompt, a `/goal` condition, "a Stop hook as a deterministic gate", or "a verification subagent as a second opinion". It also notes "The `/goal` and Stop hook versions are what let an unattended run finish correctly without you."\[14\]
- "Let Claude interview you": "For larger features, have Claude interview you first… ask Claude to interview you using the `AskUserQuestion` tool", with an example prompt ending "Keep interviewing until we've covered everything, then write a complete spec to SPEC.md."\[14\]

For R16, a lint script over `knowledge/` is exactly the "check it can run" for (a)–(c). The interview pattern is the official template for (e).

#### 1.3 CLAUDE.md, rules and auto memory (soft)

- CLAUDE.md files are "instructions you write to give Claude persistent context".\[15\] `.claude/rules/*.md` support `paths:` frontmatter for conditional loading, which is useful for a rule that loads only when Claude touches `knowledge/**`. Auto memory ("notes Claude writes itself") is machine-local. Claude Code loads the first 200 lines or 25KB of MEMORY.md, while a CLAUDE.md file loads in full up to 4 MiB. `/memory` lists and edits the files.\[15\]\[16\]
- **Risk relevant to R16:** auto memory is exactly where unsourced inferences get promoted to "facts" (issue #27430).\[3\] Recommendation: keep the project knowledge base in committed `knowledge/` files with provenance, and either disable auto memory for this project or add a rule that auto-memory notes about the project must be copied into `knowledge/` with a `claim_type`.
- The `InstructionsLoaded` hook fires "when a CLAUDE.md or `.claude/rules/*.md` file is loaded into context" and is meant for "audit logging, compliance tracking, or observability".\[6\] Use it to prove that the "offer the owner a choice" rule was actually in context, which was the open question in the A4 audit.

#### 1.4 Hooks (hard enforcement) — the relevant events

From the official hooks reference (fetched 11 Oct 2026):

| Event | Use for R16 | Decision control |
|---|---|---|
| `SessionStart` | Inject the gap ledger summary, version-drift warnings and "unmirrored citations" into context; `watchPaths` for `FileChanged` | `additionalContext` (no blocking) |
| `UserPromptSubmit` | Re-inject "open gaps: N, unpresented: M" each turn | `additionalContext`; `decision: "block"` |
| `PreToolUse` | Deny `Write`/`Edit` to output docs that cite URLs not in the mirror manifest; matches `AskUserQuestion` | `permissionDecision` allow/deny/ask/defer |
| `PostToolUse` | Lint each `knowledge/**` or output-doc write; record `AskUserQuestion` answers | `decision: "block"` + reason; exit 2 shows stderr to Claude |
| `Stop` / `SubagentStop` | Completion gate: block until gaps presented, citations mirrored, claims tagged | `decision: "block"` + reason; `additionalContext` for non-error feedback |
| `TaskCompleted` | Block marking a task done if its claims are unverified | exit 2 prevents completion |
| `InstructionsLoaded` | Audit that CLAUDE.md rules were loaded | none (observability) |
| `FileChanged` | Re-lint when mirrored docs change | none |
| `PostModelSwitch` / `SessionStart` | Detect environment changes that might stale self-knowledge | context only |

Handler types: `command`, `http`, `mcp_tool`, `prompt` (single-turn model evaluation; default timeout 30s), and `agent` (spawns a subagent that "can use tools like Read, Grep, and Glob to verify conditions"; default 60s; experimental).\[6\] Prompt hooks on Stop can return `"impossible": true` "to mark the condition as one that can never be satisfied".\[17\] That is a built-in escape hatch for gates that would otherwise loop. "The `/goal` command is a built-in shortcut for a session-scoped prompt-based Stop hook."\[6\] Hooks can also be declared in skill and subagent frontmatter. A subagent's `Stop` hook is converted to `SubagentStop`, and skill hooks support `once: true`.\[6\]

Enforcement caveats from the same page: exit 1 is non-blocking ("If your hook is meant to enforce a policy, use `exit 2`"); `onFailure: "block"` requires v2.1.295 and does not apply to Stop/SubagentStop/TaskCompleted; `additionalContext` is capped at 10,000 characters; and phrase injected text "as factual statements rather than imperative system instructions" to avoid triggering prompt-injection defences.\[6\]

#### 1.5 Subagents (structural separation)

Subagents run "in its own context window with a custom system prompt, specific tool access, and independent permissions".\[4\] For a verifier, set `tools: Read, Grep, Glob` (no Write), add `effort`, and use `omitClaudeMd: true` (v2.1.271+) so it judges only from the delegation prompt and the files. Unknown frontmatter fields are silently ignored ("Claude Code ignores a field it doesn't recognize without reporting an error"), and `claude plugin validate` (v2.1.233+) checks only whether frontmatter parses.\[4\] This silent-ignore behaviour is another way self-knowledge goes stale unnoticed.

#### 1.6 `AskUserQuestion` (the official "offer a choice" channel)

The Agent SDK docs say Claude "has clarifying questions (via the AskUserQuestion tool)", and that "each AskUserQuestion call supports 1-4 questions with 2-4 options each".\[18\] In headless mode with the `-p` flag, a PreToolUse hook can return `permissionDecision: "defer"`: "The tool doesn't execute. The process exits with stop_reason: 'tool_deferred' and the pending tool call preserved in the transcript".\[6\] That lets a pipeline hand the question to a human and resume later. **No official mechanism** makes Claude ask. Only hooks (Stop gate) or instructions can do that.

#### 1.7 Explicit "no official mechanism" list

- (a) Provenance tagging such as `[SOURCED]/[INFERRED]` in Claude Code outputs: **no official mechanism** (Citations API exists only on the platform API).
- (a) Detecting overgeneralisation beyond source scope: **no official mechanism**. Approximate it with the "retract if no supporting quote" guidance plus a prompt or agent hook.
- (b) Detecting facts a decision relied on but that are missing from a knowledge base: **no official mechanism**.
- (c) Mirroring cited sources locally: **no official mechanism** (the docs publish `llms.txt` and `.md` pages, which makes mirroring easy).
- (d) Detecting stale claims about Claude Code itself: **no official mechanism**. The authoritative sources are the live in-session tool schemas, `claude --version`, the official changelog, and the docs' "requires vX" annotations.
- (e) Forcing gaps to be shown to the owner with options: **no official mechanism**. The building blocks are the Stop hook and `AskUserQuestion`.

### 2. How the biggest players handle it

**Anthropic Research (multi-agent research system, 2025).** An orchestrator-worker design. After research, "a specialized CitationAgent … processes documents and the research report to identify specific locations for citations, ensuring all claims are properly attributed to sources."\[19\] The point of the separate agent is that it checks claims against the raw documents, not against the lead agent's memory of them.\[20\] Evaluation uses an LLM judge with separate rubric items: "Factual accuracy — do claims match sources? Citation accuracy — do cited sources match claims?" and "Source quality — did it use primary sources over lower-quality secondary sources?"\[21\] *Mapping:* this is the model for (a) and (c). Separate the writer from a verifier that has only the sources and the output.

**Anthropic context engineering (29 Sep 2025).** "Structured note-taking, or agentic memory, is a technique where the agent regularly writes notes persisted to memory outside of the context window… Like Claude Code creating a to-do list, or your custom agent maintaining a NOTES.md file."\[22\] *Mapping:* (b). Observed runtime behaviour (thresholds, env vars) must be written to a file the moment it is observed, not left in context.

**Anthropic long-running harness (26 Nov 2025, Justin Young).** An initializer agent creates "a claude-progress.txt file that keeps a log of what agents have done" and a feature list in which features start as "failing". "We prompt coding agents to edit this file only by changing the status of a passes field… we landed on using JSON for this, as the model is less likely to inappropriately change or overwrite JSON files compared to Markdown files."\[23\] *Mapping:* (b) and (e). Keep the gap ledger as JSON with a status field that the agent may only advance (`open → presented → decided`), never delete.

**How Anthropic teams use Claude Code.** Teams maintain CLAUDE.md files in git and use "end-of-session documentation updates", a loop in which Claude Code helps refine the Claude.md files based on actual usage.\[24\]\[25\] Boris Cherny's widely reported workflow (InfoQ, Jan 2026) says "the most important tip is to give Claude a way to verify its work through a feedback loop."\[26\] *Mapping:* (b). End every session with an explicit "what did I observe that is not in `knowledge/`?" step, enforced by a Stop hook.

**GitHub Spec Kit.** Its spec-driven methodology tells the agent to "Mark all ambiguities: Use [NEEDS CLARIFICATION: specific question]" and "Don't guess", and its quality checklist contains "No [NEEDS CLARIFICATION] markers remain".\[27\] `/speckit.specify` caps markers at 3 and presents options to the user,\[28\] and `/speckit.clarify` replaces each marker with the user's answer.\[29\]\[30\] Issue #2181 proposes rendering these through Claude Code's native `AskUserQuestion`.\[31\] The Xebia guide warns that the markers "only catch what the model identifies as ambiguous".\[30\] *Mapping:* (a) and (e). It is the most mature public convention for turning uncertainty into an explicit, machine-checkable marker.

**Karpathy's "LLM Wiki" pattern (2026) and successors.** The gist defines a Lint operation: "contradictions between pages, stale claims that newer sources have superseded, orphan pages… data gaps that could be filled with a web search."\[32\] rohitg00's "LLM Wiki v2" makes the R16 point exactly: "Confidence 0.85 doesn't distinguish 'verified from official docs' from 'the agent guessed this last session.' Without an Epistemic Layer, inferences written back into memory become indistinguishable from sourced facts." It proposes tracking "Claim Provenance (source chain)".\[33\] *Mapping:* (a), (b) and (d).

**Academic practice.** The "Claude Code Complete User Handbook" (arXiv 2608.26742) keeps a verification ledger. Each product claim "was adjudicated against the raw text of the primary documentation page", summaries were discarded when they disagreed with raw text, and claims that could only be settled against a running CLI appear "as UNVERIFIED in the open list… with the local check that closes it". It was verified against CLI 2.1.241 and re-verified against 2.1.246.\[34\] *Mapping:* this is a ready template for (a) and (d): version-stamped claims plus an explicit UNVERIFIED list with closing checks.

### 4. Recommended implementation for this project

*Everything in this section is my design, built from documented primitives. It is not something a source describes end to end, and I have not tested it.*

**Step 1 — Provenance schema (a, b, d).** Each `knowledge/` entry gets frontmatter or a table row:
```yaml
id: K-042
claim: "Mid-run backgrounding moves a running Bash command to background"
claim_type: sourced | observed | inferred   # observed = seen at runtime, not in docs
scope: "Applies to Bash tool only; source names MCP approvals only"   # what the source does NOT say
source: knowledge/docs/code.claude.com/hooks.md#L331
quote: "<verbatim text>"
observed: {date: 2026-10-10, cc_version: 2.1.29x, env: local|cloud, evidence: transcript path}
cc_self_knowledge: true    # claims about Claude Code itself → version-gated
```
The `scope` field is the specific fix for "waiting = inactivity". The verifier must state what the source does *not* cover.

**Step 2 — Rules (soft, loaded conditionally).** In `.claude/rules/knowledge.md` with `paths: ["knowledge/**", "outputs/**"]`, put the three official anti-hallucination rules (I don't know / quote first / retract if unquoted), plus "Never generalise beyond `scope`; inferences must be tagged `inferred` and listed in `gaps.json`."

**Step 3 — PostToolUse lint hook on `Write|Edit` (hard).** A script, run with `if: "Edit(knowledge/**)"` and similar patterns, that exits 2 with stderr if:
- a claim lacks `claim_type`;
- a `sourced` claim's quote is not found verbatim (grep) in the mirrored file;
- an output doc cites a URL absent from `knowledge/docs/manifest.json` (claude-wiki pattern);
- a `cc_self_knowledge` claim lacks `cc_version`.
Exit 2 on PostToolUse "shows stderr to Claude; the tool already ran",\[6\] so Claude fixes it in the same turn. Do not use exit 1, which is non-blocking.

**Step 4 — Scope checker for overgeneralisation (judgement).** Use an `agent` hook on SubagentStop of the writer subagent, or a dedicated `kb-verifier` subagent (`tools: Read, Grep, Glob`, `omitClaudeMd: true`). For each claim it compares the claim's quantifiers and subject with the quote and returns `ok:false` when the claim is broader than the quote. This is the CitationAgent pattern in miniature.

**Step 5 — Decision → fact dependency check (b).** Every decision in an output doc carries `relies_on: [K-…]`. A Stop command hook verifies that every referenced ID exists. It also greps the session's Bash commands and outputs (`transcript_path`, or `last_assistant_message` on Stop) for env-var patterns (`CLAUDE_[A-Z_]+`), numeric thresholds with time units, and `jq`/binary dependencies inside hook scripts. Any that are not present in `knowledge/` become `gaps.json` entries automatically. *Inferred heuristic:* this would have caught `CLAUDE_AUTO_BACKGROUND_TASKS`, the 120-second threshold and `jq`.

**Step 6 — Mirroring (c).** A `/mirror` skill or command fetches each cited URL (prefer the `.md` versions that code.claude.com publishes, and raw files for GitHub docs) into `knowledge/docs/<host>/<path>.md` with `source_url`, `fetched_at` and a hash, then updates `manifest.json`. A PreToolUse hook denies writes to output docs that introduce unmirrored URLs. Alternatively, vendor a maintained mirror as a submodule (stavarengo, ericbuess) for Claude Code docs.

**Step 7 — Staleness of Claude Code self-knowledge (d).** A SessionStart command hook:
- reads `claude --version`, compares it with the highest `cc_version` in `knowledge/`, and lists `cc_self_knowledge` claims verified on older versions;
- optionally diffs Piebald's tool-description changelog or the official changelog for the tools named in those claims;
- injects the list via `additionalContext`, with an instruction to re-verify against the **in-session tool schema** (the authoritative source: in R16 the session's Agent schema contradicted O0:62).
Add a rule that any claim of the form "tool X has / lacks field Y" must be recorded as `observed` with date and version, citing the in-session schema or a docs line with a "requires vX" annotation.

**Step 8 — Gap escalation with owner choice (e), the core of the A4 finding.**
- `gaps.json` entries: `{id, description, blocking_decision, status: open|presented|decided, options, owner_choice, presented_at}`. The agent may only advance status (harness JSON pattern).
- Stop command hook: if any gap has `status: open` and `stop_hook_active` is false, return `{"decision":"block","reason":"N knowledge gaps are unpresented. Use AskUserQuestion: for each gap offer options (a) mirror/verify now, (b) record as inferred and proceed, (c) drop the dependent decision. Then update gaps.json."}`.
- PostToolUse hook on `AskUserQuestion` (narrow matcher, no catch-all): write the question, options and answer into `gaps.json` and `decisions.log` (hivemind pattern). This gives the auditable evidence that A4 lacked.
- Headless or cloud runs: a PreToolUse `defer` on `AskUserQuestion` ends the run with `tool_deferred` so the owner can answer later. Alternatively, let the Stop hook exit with `continue:false` and a `stopReason` listing the gaps, so the run never "silently notes" them.
- Respect the loop cap. After the gate has fired once (`stop_hook_active`), allow the stop but emit `systemMessage` to the user listing the unpresented gaps. That way the failure is still *surfaced* even if Claude does not comply.

**Step 9 — Ownership.** The mechanism note says "nobody owns surfacing gaps". Name an owner. The `kb-steward` subagent and the Stop hook own detection, and the human owner owns decisions. Record this in CLAUDE.md so audits can test against it.

## Caveats

- **Version sensitivity:** much of this depends on features added recently (e.g. `onFailure` v2.1.295, per-invocation `effort` v2.1.292, `omitClaudeMd` v2.1.271). Check `claude --version` before relying on them. Agent hooks are explicitly experimental.
- **Secondary-source items:** the Stop-block cap itself is official: `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` defaults to 8, and "Set to 0 to disable the cap", per the env-vars page. Only the v2.1.143 introduction date comes from third-party guides. The Citations figures (10%→0% source hallucinations, a 20% increase in references per response) are Thomson Reuters' own numbers, quoted in Anthropic's launch post, and nobody has independently verified them.
- **Bugs:** `AskUserQuestion` interacted badly with PreToolUse hooks in several reported issues, and some may be fixed now. Avoid catch-all matchers and test on your version.
- **Soft vs hard:** markers, tags and fact-checker skills only work if the model applies them. Spec Kit's own users note that markers "only catch what the model identifies as ambiguous".\[30\] Hooks enforce *structure* (tag present, quote found, file mirrored, gap presented), not *truth*. Judging overgeneralisation is still model-based.
- **Unofficial sources:** docs mirrors and Piebald's extracted prompts are unofficial; Context7 is a third-party remote service. Marketplace skills (mcpmarket, Lenz) were not code-reviewed for this report.
- **Inferred designs:** Section 4 combines documented primitives in ways that no source describes end to end. I have not tested them.

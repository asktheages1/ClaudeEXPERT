# Making Claude Code's Judgments Explicit, Exhaustive and Honest About Disagreement (R10)

No single setting in Claude Code fixes R10. The approach that works with the current tools has four parts: (1) write the criteria, severity scale and evidence inventory down as files before any judging starts; (2) have a separate, read-only judge in a fresh context apply them, not the author; (3) use deterministic command hooks (PostToolUse/Stop) to check that every input maps to an output, that severities match the scale, that dispositions match their labels, and that a non-empty "open disagreements / uncertainties" section exists; (4) send every open item to the human through the main session's AskUserQuestion tool, because subagents cannot ask the human directly. Anthropic's own docs and engineering posts support parts 2 and 4 and the general hook mechanism. Parts 1 and 3, the scale and coverage validators, have no official implementation, so you must script them yourself.

## TL;DR

- **Separate author from judge, and give the judge written criteria.** Anthropic's harness-design post found that agents "reliably skew positive when grading their own work" and that "tuning a standalone evaluator to be skeptical turns out to be far more tractable than making a generator critical of its own work".\[1\] Claude Code's best-practices docs recommend a fresh-context "adversarial review step".\[2\] Research shows self-preference survives even objective rubrics: Pombal, Rei & Martins (arXiv 2604.06996, a preprint, not confirmed peer-reviewed) tested on IFEval and LiveCodeBench and found that on HealthBench "SPB skews model scores by up to 10 points". So a cross-model judge or a judge ensemble is better than a same-model judge.
- **Exhaustiveness, scale consistency, dedup and label honesty are only reliable as code.** Use command hooks with exit code 2 or `decision: "block"` that validate a structured ledger: every evidence ID is covered, every severity comes from a frozen scale file, there are no duplicate keys, "accepted" requires a matching change, every "untested/unknown" claim carries an epistemic marker, and no trait words appear in causal analysis. Anthropic ships no validators for any of this. Prompts and CLAUDE.md are advisory only; the docs say so explicitly.\[2\]
- **Escalate, don't resolve silently.** Require a mandatory "Disagreements & Uncertainties for the owner" block, enforced by a Stop hook, and route it through AskUserQuestion in the main thread. Subagents, including reviewers, cannot call AskUserQuestion, so they must return questions to the main session instead of guessing.\[3\] The best ready-made community patterns are cross-model review tools that tag findings `[disputed]` (SameerKhan/model-crosscheck) and obra/superpowers' `receiving-code-review` skill ("IF any item is unclear: STOP … ASK for clarification").\[4\]\[5\]

## Key Findings

1. **Anthropic officially names self-evaluation bias and prescribes separation.** Verified: harness-design post (Mar 2026), best-practices docs ("the agent doing the work isn't the one grading it").\[1\]\[2\]
2. **Hooks are the only deterministic layer.** Verified: the docs say "Unlike CLAUDE.md instructions which are advisory, hooks are deterministic and guarantee the action happens".\[2\] Output styles "[don't] guarantee that something always happens".\[6\]
3. **Anthropic's grader guidance maps directly onto R10's method failures.** Verified, from "Demystifying evals for AI agents" (Jan 2026):
   - "vague rubrics produce inconsistent judgments"\[7\]
   - grade each rubric dimension "with an isolated LLM-as-judge"\[7\]
   - give the judge a way out by returning "Unknown"\[7\]
   - use "coverage checks" that "define key facts a good answer must include"\[7\]
   - "A good task is one where two domain experts would independently reach the same pass/fail verdict."\[7\]
4. **AskUserQuestion is unavailable in subagents.** Verified, from the Agent SDK docs: "AskUserQuestion is not currently available in subagents spawned via the Agent tool".\[3\] GitHub issues #12890 and #34592 report the same in Claude Code, even though older sub-agent docs implied pass-through for foreground agents.\[8\]\[9\] Any judge or reviewer subagent therefore needs a "questions for owner" return channel.
5. **No official mechanism exists** for severity-scale conformance, coverage matrices, deduplication, a disagreement registry, trait-attribution bans or "rejection vs acceptance" label checks. These must be built as command hooks or scripts. (Inferred from absence across the docs reviewed.)
6. **Big vendors converge on the same three ideas:** independent verification passes, explicit severity/confidence labels, and humans keeping final authority. Verified:
   - Anthropic Code Review: parallel agents and a verification step; findings are "deduplicated, ranked by severity" on three levels (🔴 Important, 🟡 Nit, 🟣 Pre-existing); the check run "always completes with a neutral conclusion so it never blocks merging" (Code Review docs).
   - Cursor Bugbot: eight randomized passes, majority voting, a validator model.\[10\]
   - Devin: confidence scores, and it waits for approval when not 🟢.\[11\]
   - GitHub Copilot cloud agent: cannot approve its own PRs.\[12\]

## A. Official recommendations and mechanisms (Anthropic)

Enforceability legend: **Advisory** = a prompt the model may ignore; **Deterministic** = a script or hook decides; **Separate agent** = an independent model judges, probabilistically.

### A1. Fresh-context adversarial review / verification subagent
- **Source:** Claude Code best practices, https://code.claude.com/docs/en/best-practices
- **Sub-themes:** 4, 2, 5
- **Mechanism:** "Before treating a task as done, have a subagent review the diff in a fresh context and report gaps. … A reviewer running in a fresh subagent context sees only the diff and the criteria you give it, not the reasoning that produced the change, so it evaluates the result on its own terms." The docs also list "a verification subagent … has a fresh model try to refute the result, so the agent doing the work isn't the one grading it". They also recommend a Writer/Reviewer pattern across two sessions: "A fresh context improves code review since Claude won't be biased toward code it just wrote."\[2\]
- **For R10:** hand the judge (a) the complete evidence inventory, (b) the written criteria and scale, and (c) the author's draft, never the author's reasoning. Ask it to refute.
- **Enforceability:** Separate agent. It becomes mandatory only when it is triggered by a hook (see A3).
- **Effort:** Low. One `.claude/agents/judge.md` file with `tools: Read, Grep, Glob` (read-only).
- **Limitations:** Same model family means shared blind spots (see A10). The judge is only as good as the criteria you give it.
- **Evidence:** Anthropic's harness post found separation "a strong lever".\[1\] No quantitative number is given for the subagent pattern itself.

### A2. Bundled `/code-review` skill and managed Code Review with REVIEW.md
- **Source:** https://code.claude.com/docs/en/code-review
- **Sub-themes:** 1, 4, 5
- **Mechanism:**
  - Multiple agents analyse a diff in parallel, then "a verification step checks candidates against actual code behavior to filter out false positives".\[13\]
  - Findings are tagged by severity and "don't approve or block your PR".\[13\]
  - A repo `REVIEW.md` reaches "every finding and verification agent directly". It can redefine what each severity means for the repo, and it supports evidence rules such as "behavior claims need a file:line citation in the source, not an inference from naming".\[13\]
- **For R10:** use the REVIEW.md idea, a single criteria file that all judges read, as your severity scale plus evidence-citation rule. It is the closest official analogue to "criteria written before judging".
- **Enforceability:** Separate agent plus an advisory criteria file.
- **Effort:** Low for the local skill. The managed service is Team/Enterprise only, and Anthropic's own Code Review docs say "Each review averages $15-25 in cost, scaling with PR size, codebase complexity, and how many issues require verification", with reviews finishing "in 20 minutes on average".
- **Evidence:** Anthropic says that internally "less than 1% of findings are marked incorrect", that 84% of PRs over 1,000 lines receive findings (7.5 issues on average), and that substantive review rose from 16% to 54% of PRs.\[14\]\[15\] These are vendor-reported figures.
- **Limitation:** The service is built for code diffs, not prose analyses or ledgers.

### A3. Hooks: Stop / SubagentStop / PreToolUse / PostToolUse / UserPromptSubmit
- **Source:** https://code.claude.com/docs/en/hooks and https://code.claude.com/docs/en/hooks-guide
- **Sub-themes:** all; this is the enforcement substrate.
- **Mechanism (verified):**
  - Exit code 2 blocks. On Stop/SubagentStop, "exit code 2 … sends Claude back to keep working".\[16\]
  - JSON `{"decision":"block","reason":"…"}` on Stop "prevents Claude from stopping", and the reason becomes Claude's next instruction.\[16\]\[17\]
  - PreToolUse can deny a tool call.\[16\]
  - UserPromptSubmit can inject context or reject a prompt.\[16\]
  - Handler types: `command`, `http`, `mcp_tool`, `prompt` (single-turn LLM evaluation) and `agent` (a subagent with Read/Grep/Glob; "Agent hooks are experimental").\[16\]
  - The `/goal` command "is a built-in shortcut for a session-scoped prompt-based Stop hook".\[16\]
  - A Stop hook placed in subagent frontmatter becomes SubagentStop.\[18\]
- **Loop guard:** the `stop_hook_active` input flag. There is also a cap on consecutive Stop-hook continuations. dgiotas/dev-flow PR #7 says it is "Confirmed by the hooks, hooks-guide and env-vars docs: the cap exists, default 8, env var, 0 disables it, all Stop hooks run and share one count", and skylos.dev says it checked the eight-continuation cap "against Anthropic's hooks reference on 10 Oct 2026". `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` raises the cap (reported since v2.1.143). Both of these sources are secondary.
- **Exit 1 does not block.** It is a non-blocking error.\[18\]
- **For R10:** a command-type Stop hook runs the ledger validator (section D) and blocks until coverage, scale, dedup, label and dissent checks pass. A PreToolUse hook denies Edit/Write on `criteria/severity-scale.md` while a judging phase is active, which prevents ad hoc redefinition of the scale.
- **Enforceability:** Deterministic for command hooks. Prompt and agent hooks are probabilistic; one guide warns not to use them for hard boundaries.\[19\]
- **Effort:** Medium (scripting).
- **Limitations:** The block cap means a stubborn model can eventually stop anyway. Hooks check structure, not truth. Agent hooks are experimental.\[20\]

### A4. AskUserQuestion, plan mode and "interview me"
- **Sources:**
  - Best practices (above)
  - Agent SDK "Handle approvals and user input", https://code.claude.com/docs/en/agent-sdk/user-input
- **Sub-themes:** 3, 8
- **Mechanism:**
  - The best-practices docs recommend "Interview me in detail using the AskUserQuestion tool … dig into the hard parts".\[2\]
  - In the SDK, each call supports "1-4 questions with 2-4 options each". If you restrict `tools`, you must include AskUserQuestion.\[3\]
  - "Subagents: AskUserQuestion is not currently available in subagents spawned via the Agent tool."\[3\]
  - Background subagents' clarifying calls fail and the subagent continues without an answer (secondary guide and GitHub issue #20275).\[21\]\[22\]
  - Auto mode "nudges Claude to keep working without stopping for clarifying questions". GitHub issue #61031 says v2.1.146 added an exception when you explicitly ask for AskUserQuestion or a skill depends on it; the docs did not yet reflect this.\[23\]
- **For R10:** make the main thread the only escalation point. Subagents return a `QUESTIONS_FOR_OWNER:` block, and the main thread must turn each item into an AskUserQuestion call before finalising. Plan mode separates analysis from action, so the method and criteria can be approved first.\[2\]
- **Enforceability:** Advisory unless a Stop hook checks that each open item has an owner answer recorded.
- **Effort:** Low.
- **Limitations:** The multiple-choice format can push nuanced disagreements into options the model chose. Subagent behaviour has changed between versions.

### A5. Skills, slash commands and subagent definitions
- **Sources:** skills and sub-agents docs, as summarised in best practices
- **Sub-themes:** 1, 2, 6
- **Mechanism:** a `SKILL.md` holds reusable procedures, such as a "judgment protocol" (criteria first, enumerate evidence, map, judge, list dissent). `disable-model-invocation: true` makes a workflow manual-only. Skills and agents can embed hooks in frontmatter; `once: true` is honoured in skill frontmatter. Subagent `tools:` lets you make judges read-only.\[2\]\[18\]
- **Enforceability:** Advisory content plus deterministic embedded hooks.
- **Effort:** Low–medium.
- **Limitations:** Skills trigger on their description, so automatic triggering is probabilistic.

### A6. CLAUDE.md rules
- **Source:** best practices
- **Sub-themes:** 3, 5, 6
- **Mechanism:** persistent instructions. The docs warn that "Bloated CLAUDE.md files cause Claude to ignore your actual instructions!" and advise "IMPORTANT" on single key lines only.\[2\]
- **For R10:** use 5–8 short lines. Examples:
  - "Disagreement or uncertainty is never resolved by you; list it under 'For owner'."
  - "'Untested' ≠ 'documented false'."
  - "Causes are mechanisms, not traits."
  - "Never relabel a rejection."
- **Enforceability:** Advisory.
- **Effort:** Trivial.
- **Limitations:** This is exactly the layer R10's history shows being ignored. Pair it with hooks.

### A7. Output styles
- **Source:** https://code.claude.com/docs/en/output-styles (verified by the subagent)
- **Sub-themes:** 5, 3
- **Mechanism:** "An output style changes the instructions Claude Code gives Claude." Custom styles drop the built-in software-engineering instructions unless `keep-coding-instructions: true` is set; the field only has effect on the full system prompt (`CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0`).\[6\]
- **For R10:** an "auditor" style can force epistemic markers ([verified]/[assumed]/[unknown]) and a closing "For owner" section on every reply in the main conversation.
- **Limitations, verified:**
  - "It doesn't guarantee that something always happens or never happens."\[6\]
  - Styles do not apply to non-fork subagents, which "run their own system prompt".\[6\]
- **Enforceability:** Advisory.

### A8. Prompt-engineering guidance: "say I don't know", quotes, citations and claim verification
- **Source:** "Reduce hallucinations", https://docs.anthropic.com/en/docs/test-and-evaluate/strengthen-guardrails/reduce-hallucinations
- **Sub-themes:** 5, 2
- **Mechanism (verified):**
  - "Allow Claude to say 'I don't know'."\[24\]
  - For long documents, "extract word-for-word quotes first before performing its task".\[24\]
  - "have Claude verify each claim by finding a supporting quote after it generates a response."\[24\]
  - Also lists Best-of-N verification and restricting Claude to the provided documents.\[24\]
- **For R10:** this directly counters "untested" becoming "the documentation says no". Any claim of the form "documentation says X" must carry a verbatim quote and its location, or be downgraded to [unknown].
- **Enforceability:** Advisory. The citation requirement can be checked deterministically by regex in a hook.
- **Limitations:** Fabricated quotes are possible, so the validator should check that each quote string actually exists in the cited file (see D).

### A9. Grader and evaluator design guidance
- **Sources:**
  - "Demystifying evals for AI agents", https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents (Jan 9, 2026)
  - "Harness design for long-running application development", https://www.anthropic.com/engineering/harness-design-long-running-apps (Mar 24, 2026)
- **Sub-themes:** 1, 2, 4, 5
- **Mechanism (verified):**
  - Prefer "deterministic graders where possible, LLM graders where necessary".\[7\]
  - "create clear, structured rubrics to grade each dimension of a task, and then grade each dimension with an isolated LLM-as-judge".\[7\]
  - "return 'Unknown' when it doesn't have enough information".\[7\]
  - LLM judges "should be closely calibrated with human experts".\[7\]
  - Research outputs need groundedness, coverage and source-quality checks.\[7\]
  - Read transcripts: "we do not take eval scores at face value until someone digs into the details".\[7\]
  - The harness post adds:
    - criteria written before generation and given to both generator and evaluator;\[1\]
    - "Each criterion had a hard threshold";\[1\]
    - few-shot calibration "with detailed score breakdowns" to reduce "score drift";\[1\]
    - a "sprint contract" in which the evaluator agrees on what "done" means before work starts.\[1\]
- **For R10:** the sprint contract is the official model for "criteria before judging". The judge and the owner sign off the scale and checklist before the analysis is written. Few-shot calibrated examples for each severity level stop the scale drifting.
- **Effort:** Medium–high.
- **Evidence:** In the harness post, the solo run took 20 minutes and cost $9 and produced a broken core feature. The full harness took 6 hours and cost $200 and produced a working app.\[1\] This is qualitative, a single case.

### A10. Constitution: calibration and anti-"epistemic cowardice"
- **Source:** Claude's Constitution (Jan 2026), https://www-cdn.anthropic.com/d0636f72a9493d279ed36b33987da3430bcb5911/claudes-constitution_webPDF_26-02.02a.pdf
- **Sub-themes:** 5, 3
- **Mechanism:** Claude "acknowledges its own uncertainty or lack of knowledge when relevant, and avoids conveying beliefs with more or less confidence than it actually has".\[25\]\[26\] The text also says "Epistemic cowardice—giving deliberately vague or non-committal answers to avoid controversy or to placate people—violates honesty norms" (as quoted from the published text by secondary sources).\[27\]
- **For R10:** quote these lines in your judge prompt as the norm. They cut both ways: no inflated self-accusation ("more … confidence than it actually has") and no hedging.
- **Enforceability:** Training-level disposition; not controllable by the user.

### A11. Claude Agent SDK
- **Sub-themes:** 4, 2
- **Mechanism:** Anthropic built the generator/evaluator harness on the Agent SDK, with communication "handled via files".\[1\] For R10 you can orchestrate author → judge → validator → owner as a script with hard gates outside the model.
- **Enforceability:** Deterministic orchestration.
- **Effort:** High.

### Sub-themes with **no official mechanism**
- Severity-scale conformance checking (1): **none.** The scale can only be defined, as in REVIEW.md.
- Coverage matrix or "every input maps to an output" checks (2): **none.** Anthropic only describes the concept, as "coverage checks" in its evals post.
- A disagreement or dissent registry, or a rule that disagreement goes to the owner (3): **none.** There is the AskUserQuestion tool but no policy.
- Root-cause method and trait-attribution bans (6): **none** in the Claude Code docs.
- Deduplication and count integrity (7): **none**, apart from the managed Code Review's internal dedup.
- A clarification duty when reviewer feedback is unclear (8): **none** beyond the generic AskUserQuestion and interview advice.

## D. Gaps and the recommended stack

### Remaining gaps
1. **Same-model judge bias is reduced, not removed.** Research shows self-preference persists even with objective rubrics. Pombal, Rei & Martins (arXiv 2604.06996, a preprint) found that "judges can be more than 50% more likely to incorrectly mark them as satisfied when the output is their own", and that ensembling "helps mitigate SPB, but without fully eliminating it". Structured multi-dimensional evaluation reduced self-preference bias "by 31.5% on average" (arXiv 2604.22891).\[55\] Chae et al. (arXiv 2608.18091, Sep 2026) tested ten LLMs and found: "Under blind evaluation, self-preference disappears… self- and other-labels alone… shift scores bidirectionally." So **strip authorship labels** from what the judge sees.
2. **Hooks verify form, not truth.** A validator can confirm that a severity token is on the scale, not that it is the right severity. Only calibrated examples plus human spot checks address that.
3. **Escalation is architecturally constrained.** Subagents cannot ask the human; auto mode discourages questions; the Stop block cap ends loops after ~8 continuations (secondary sources).\[3\]\[18\]\[23\]
4. **Self-criticism as performance** (fabricated self-accusations) has no tool-level fix. Only evidence requirements apply: every accusation, of self or of the auditor, needs a cited transcript or file line, or it is struck.

### Recommended stack (in order of value per effort)

**Layer 0: files written before any judging (criteria-first; sub-themes 1, 2).**
- `criteria/severity-scale.md`: levels, a definition for each, and two calibrated examples per level (Anthropic's few-shot calibration). Frozen with a hash.
- `criteria/causal-categories.md`: a closed enum, e.g. `rule-breach | method-error | missing-information | tool/environment-limit | spec-ambiguity`, and a ban on trait words.
- `evidence/inventory.jsonl`: one row per evidence item (deviation, environment fact, built-in, check, auditor point) with a stable ID. Have a *separate* subagent produce it from the raw sources, and the owner approve it, before analysis starts. This is your "sprint contract".

**Layer 1: structured output (sub-themes 2, 5, 7).**
- The analysis is written as `ledger.jsonl`, one row per finding, with these fields: `id, evidence_ids[], claim, epistemic_status ∈ {verified, assumed, unknown, untested}, evidence_quote, evidence_loc, severity, severity_rationale_ref, disposition ∈ {accepted, rejected, deferred, needs-owner}, change_ref, cause_category`.
- The prose report is generated *from* the ledger, so prose cannot hide items the ledger lacks.

**Layer 2: deterministic validators (command hooks; sub-themes 1, 2, 5, 6, 7).**
Run on PostToolUse (Write/Edit of the ledger) and on Stop. Exit 2 or `decision:"block"` with a precise reason. The checks:
- **Coverage:** every inventory ID appears in ≥1 ledger row's `evidence_ids`, or in an explicit `out_of_scope` row with a reason. List the missing IDs in the reason. This fixes the "MISSED" rows.
- **Scale conformance:** `severity` ∈ the scale levels. The scale file's hash is unchanged since freeze. A PreToolUse hook denies edits to `criteria/` during judging, so redefining the scale requires a human.
- **Dedup:** normalised `(claim, evidence_ids)` keys are unique. The reason reports duplicate counts. This fixes the seven inflated rows.
- **Label integrity:** `accepted` ⇒ non-empty `change_ref`; `rejected` ⇒ non-empty rationale and no "accepted/adopted" wording in the prose for that ID.
- **Epistemic integrity:** any claim matching /documentation (says|states)|docs say/ requires `evidence_quote`, and the quote string must exist in the cited file (grep). `untested`/`unknown` claims cannot carry the wording "is false/does not". A refusal whose rationale is only "untested" is flagged as circular.
- **Causal integrity:** `cause_category` is in the enum; a blocklist of trait words (e.g. lazy, laziness, convenience, sloppy, and your own languages' equivalents such as "lenistwo", "wygoda") in rationale or RCA fields blocks. Claims of a "common denominator" must list the supporting row IDs, with ≥N rows and no counterexamples left unaddressed.
- **Dissent present:** the report contains a `## For the owner: disagreements & uncertainties` section, and every `needs-owner` row and every reviewer/auditor objection not accepted appears there verbatim. An empty section requires the literal line "None — checked rows X–Y".

**Layer 3: an independent judge (sub-themes 4, 1).**
- A read-only `judge` subagent sees the inventory, the criteria and the ledger, with authorship labels stripped. It scores each dimension separately (coverage, severity fit, label correctness, reasoning validity), may answer "Unknown", and must output `DISSENT:` and `QUESTIONS_FOR_OWNER:` blocks.
- For high stakes, add a cross-vendor pass (C3/C4) and keep `[disputed]` items. Do not filter down to consensus only.
- Optionally run it as a SubagentStop/Stop `agent` hook (experimental) so it fires automatically.\[19\]\[20\]

**Layer 4: escalation (sub-themes 3, 8).**
- The main session converts each `QUESTIONS_FOR_OWNER` item, each unclear auditor point and each `needs-owner` row into AskUserQuestion calls. Owner answers are written into the ledger as `owner_decision`.
- A Stop hook blocks while any `needs-owner` row lacks `owner_decision`. Unclear reviewer points follow the superpowers rule: STOP and ask; never reinterpret silently.\[5\]

**Layer 5: advisory reinforcement (cheap; sub-themes 5, 6).**
- 5–8 CLAUDE.md lines (A6).
- An "auditor" output style with epistemic markers (A7).
- A blameless-RCA skill based on the Google SRE format: contributing factors, not individuals; every self-accusation or auditor-blame claim needs a cited line.\[39\]

**Expected effect (inferred).** Layers 0–2 deterministically remove the countable R10 failures: missed rows, duplicates, off-scale severities, a redefined scale, mislabelled dispositions, unquoted "docs say no" claims, trait causes, and hidden dissent. Layers 3–4 reduce, but cannot eliminate, the judgment failures: wrong-but-valid severities, self-favouring narratives and overgeneralisation.

## Caveats

- **Vendor metrics are self-reported:** Anthropic's <1% incorrect findings; Cursor's resolution rate, which its "Closing the code review loop with Bugbot Autofix" post says "(i.e., percentage of bugs resolved by users before the PR is merged) has increased from 52% to 76%"; Devin's confidence scores.
- **Details from secondary sources:** the Stop hook cap of 8 and `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`, the Haiku default for prompt hooks, agent hooks' 50-turn limit, the auto-mode AskUserQuestion exception, and the superpowers star count.\[56\]\[57\] The official pages were not fully verified for these.
- **AskUserQuestion in subagents:** behaviour has differed between Claude Code docs, SDK docs and actual releases.\[3\]\[8\]\[21\] Test your version.
- **Community repos:** mostly small and fast-moving; review skill files before installing (honnibal's warning that skills are "maximum privilege remote code execution").\[52\]
- **Inferred, not tested:** the validator designs in section D are my synthesis. No source reports measured results for this exact stack.

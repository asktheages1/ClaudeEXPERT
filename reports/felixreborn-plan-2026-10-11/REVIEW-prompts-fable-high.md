## 1. Verdict

The prompts are unusually concrete (commands as done criteria, fixtures, n stated, worktree isolation for probes) and most hook mechanics they rely on are backed by O2 §A5–A6 and the 2026-10-11 findings. They are not executable in order as written: four prompts (S00, S05, S06, S13) edit or move sections of a root `CLAUDE.md` that does not exist in FelixReborn (they describe the ClaudeEXPERT file), the trusted-CI design makes every PR from S01 onward red and unmergeable under the branch protection it asks for, and three S08/S12 hook designs would block or recurse on themselves. One revision that fixes the five items below, plus the per-file points marked important, makes the sequence runnable; nothing in the plan's goals needs to be dropped.

### Ranked top 5 required changes

1. **Target the real FelixReborn `CLAUDE.md` and import the conflict list (S13 blocking; S00, S05, S06 important).** S13 §2 removes "the KB table, the evidence-tag legend, 'Known open conflicts', 'Freshness', 'Live lookups'" and moves "Reviewing designs for other Claude systems": none of these sections exists in the skeleton (`grep -c` for those headings on the uploaded skeleton → 0 [MEASURED here]); they are sections of *this* repo's CLAUDE.md. The "Known open conflicts" list and the evidence-tag table live only in ClaudeEXPERT `CLAUDE.md`, not in `knowledge/` (`grep -n 'Known open'` over `knowledge/*.md` → 0 [MEASURED here]), so they never reach FelixReborn; S05 §3 then has nothing to move and S06 §3 "the one copy of the open-conflicts list (moved from `recheck-and-conflicts.md`)" is empty. Fix: S00 precondition adds a copy of ClaudeEXPERT `CLAUDE.md` as `knowledge/CLAUDEEXPERT-CLAUDE.md`; S01 adds it as a 7th source (conflict list and evidence-tag legend → `recheck-and-conflicts.md` / later `knowledge/CLAUDE.md`, routing table → drop); S13 §2 is rewritten against the skeleton's real sections (skel l.23–24, l.44, l.46, l.65, l.68 as listed in `01-przeglad` §3).
2. **Make the gate-file PRs mergeable (S00 blocking).** S00 §6 makes the required job fail "if the diff touches `.claude/**`, `.github/**`, `tools/kb_*`, `tools/test_hooks.sh`, `knowledge/topics.json`" and §7 asks for branch protection with that check required and "Include administrators". Every later PR touches `tools/kb_*` (S01 adds `kb_migrate*`, S03/S04/S05/S06 extend `kb_check.py`, S06 adds `kb_build.py`, S08–S12 add hooks and settings). Result: S01–S13 are all red and the owner cannot merge any of them without switching protection off each time (PLAN §10 Q5 names this consequence; the prompts do not resolve it). Fix: two jobs — `kb-check` (content checks, required) and `gate-files-changed` (informational, not required, prints the list); or require a PR review instead of a red check. Also: define `--root` (S00 §4 lists only `--phase/--tree/--worktree/--self-test`, §6 calls `--root pr`); fetch with `fetch-depth: 0` or diff against `github.event.pull_request.base.sha` (a default shallow checkout has no `origin/main...<head>` merge base); pass the phase explicitly from `main`'s `STATE.md`, not from `pr/knowledge/STATE.md` (data from the PR would choose how strictly it is checked); add the `kb-pre-step-N` tag the plan's rollback unit (PLAN §0.3) requires — no prompt creates it.
3. **Fix three S08 hook designs before they go live (blocking).** (a) Recursion: push gate (a) runs `bash tools/test_hooks.sh`; `test_hooks.sh` runs every fixture, including the push-gate fixture, which runs `test_hooks.sh` again. Add a guard (`KBGATE_TESTING=1` set by the harness, honoured by the push gate). (b) Mode: §Rules say `KBGATE_MODE` default `log` = "record, never block", but the push gate is meant to block from S08 (PLAN §6 3b; `onFailure: "block"`). State that the push gate honours only `off`. (c) Size: SubagentStart `additionalContext` = `agent-rules.md` (≤ 3,000 chars) + the map (≤ 9,500 bytes) can reach 12,500 chars; O2 §A6: "10,000-char limit per `additionalContext` … overflow goes to a file and Claude gets a 2,000-char preview". Set one combined budget ≤ 9,500 and have `kb_check` enforce it.
4. **Remove the self-locks and the contaminated probe in S12 and S06 (important).** S12 §4 switches hooks to `block` (live at once, O0 §3 "hooks … work in session") and §5 installs a ConfigChange hook that exits 2 on `project_settings` and `ask` rules on `.claude/settings.json`, `tools/kb_*`, hooks — *before* §6 (deny list edit of the same settings file), the live tests, and the post-review fixes. The session then blocks or prompts itself; in the cloud a pending `ask` is inactivity and the session may expire (O0 §7 T6-08). Order: all settings/hook edits first, `ask` rules and the ConfigChange hook as the final single write, and the hooks exempt the building session via `KBGATE_MODE=log` set in the environment until the end. S12 §3 A/B: S10 §2 injects "Read in full … before anything else" into every gated agent's prompt "in `log` mode still", so arm B is told to read too; run the A/B with the Agent-hook off, and redesign it (see S12 below) or the result is uninformative. S06 §6: `.claude/agents/probe-omit.md` is created in the session that needs it; O0 §3: "restart: agents dir created mid-session" — the custom type is not available. Create `.claude/agents/` (with the probe definition) in S05.
5. **Make "read in full" and the reviewers' reading real (important, COMMON + S00/S02/S04).** COMMON §1 defines "Read in full" as Read with no offset/limit, then S00 lists `O0 … (sections 1, 2, 4, 7, 8)` and `O2 lines 1–200 and section D` under that heading, S02 lists "the headers (first 15 lines)". Either read whole files (O0 39,247 B and O2 39,951 B both fit one Read: O0 §1 "Read: 25,000 tok. per call", O0 header 17.8k tokens) or move partial items to a separate "Read in part (say so)" list. COMMON §4 tells reviewers "`git diff origin/main...HEAD` (read all of it)" through Bash: O0 §6 "Bash inline ~30,000 chars", F:2026-10-11 "the model saw only the 2 KB preview"; S01's diff is ~140 KB, S03/S04 tens of KB. Have the session write `Warsztat/diff-<Sxx>.patch` (and per-file patches) and tell reviewers to Read them in parts. Add to the reviewer prompt: "edit nothing except your review file" (they are general-purpose with Bash; O0 §8 "read-only" needs no Bash). Finally, nothing verifies agents' reads by script before S08 (the owner's requirement): the PostToolUse read logger (S08 §4) has no dependency on S01–S07 and can be installed in S00 in log mode via project settings — it also gives S12 baseline rows from seven real sessions instead of one.

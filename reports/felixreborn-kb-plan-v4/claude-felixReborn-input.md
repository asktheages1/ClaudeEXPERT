# FelixReborn — instructions for Claude
FelixReborn is the owner’s base template for every future Claude Code project and, at the same time, the laboratory where that template is built and proven. 
The product is the folder Gotowe/: CLAUDE.md, .claude/settings.json, hooks, agents, skills and tests that other projects copy. 
You are both the test subject and the architect of the tests: you propose and build mechanisms that constrain you, but you never certify them. A
 mechanism counts as real only when tools/test_hooks.sh shows it blocking a dummy action, an independent reviewer has read it, and the owner has merged the PR. 
 A rule without such a test is advice and is labelled as advice. Self-reports (“it works”, “I checked”) are not evidence here; transcripts, test output and hook logs are. 
 Work in Warsztat/; only accepted work is promoted to Gotowe/.

## Start of every session
- A SessionStart hook prints: version, branch vs `origin/main`, the top of `STATUS.md`, and „<health check due>” when the health check is due. Then find what the task needs through `MAPA.md` §1 (task → file, size in KB) and read only those files; markdown ≤ 40 KB fits one Read, number-heavy files less (measure with the Read counter). - Claude Code behaviour (hooks, permissions, agents, settings, cloud): do not rely on memory, it is older than the tool. Check `<docs>/FINDINGS.md` and the official docs first; in a repository with the knowledge base, `<kb>/O0-how-claude-works.md`.

## Verification (every change)
- Never report "works" without running it. Write the test first and see it FAIL without the fix; then `<tests script>` all green. Conventions: `<docs>/TESTS.md`.
- Non-trivial change, and any plan, analysis or prompt the owner will act on: one independent read-only reviewer (`.claude/agents/reviewer.md`; fresh context; it sees only the diff or draft you wrote, code access and the criteria; adversarial task "find the case where this breaks"; output per finding: severity, file:line, reproduction, fix; "nothing found" is a valid result) before packaging, merging or handing over. ## Enforcement and its limits
- Hard (Claude Code or the server 
enforces): `.claude/settings.json` deny rules; hooks in `.claude/hooks/` with exit 2 (<force-push and history rewrite blocked; push to `main` blocked while `doc_check` is red or docs did not change with the code; edits in `<frozen dir>` blocked; GitHub MCP write tools denied: write through git only>); server-side branch protection. Everything else in this file is advice: for what must never happen, ask the owner for a hook or a deny rule instead of a sentence here.
- Project deny rules and hooks load only when the session or `claude -p` starts at the repository root, in a session with this repository alone: start every `claude -p` from the root. Known bypasses, recorded in `tools/test_hooks.sh` as „passes”, never „fixed”; do not use them: a push from inside a script, `sh -c`, `xargs`, `$(…)`, git aliases, `GIT_DIR`; `grep -r`, python or a script reading a denied path (deny rules on sensitive PC paths narrow this; `blockReadsOutsideWorkingDirectories` unmeasured). Hard on every write to GitHub is only server-side branch protection — for a private repository only on a paid plan and with admin bypass disabled; check it is on, otherwise `main` is guarded only by hooks. The sandbox is off unless `sandbox.enabled`; in the cloud it is unverified.
- A hook that times out or crashes lets the action through unless it sets `onFailure: "block"` (Claude Code ≥ 2.1.295). Set it only on narrow gates (`Bash(git push *)`, edits of protected paths), never on a hook that runs on every Bash, Edit or Write call: a broken or unstartable hook would then block those calls, including the edit that switches hooks off. If a hook blocks honest work: `"disableAllHooks": true` in `.claude/settings.local.json`, with the owner's approval; emergency path for the owner: a `.bat` that sets it on the PC, a settings change on GitHub plus a new session in the cloud.
- When changes take effect: hooks and permission rules at once (a broken hook breaks this session immediately: test a scratch copy with `tools/test_hooks.sh` first); `model` and `effortLevel` at start; this file only in a NEW session (new agents and the classifier keep the start version); agent definitions after a few seconds, but a NEW session if `.claude/agents/` was created in this one; an edited skill must be invoked again, a new skills directory needs `/reload-skills`. The auto mode classifier may refuse edits of this file or `.claude/`, or their merge → leave them in a branch/PR for the owner.
- Health check: skill `/<health-check>` when the start hook says it is due (90 days after „Last review”), after a model change and after a new Claude Code version: changelog delta, `/doctor prompt-audit <file>` on this file and `.claude/`, deny rules re-tested on dummy files, effort re-tested on a real task, caps re-measured with the Read counter.
